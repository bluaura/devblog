투자노트(bluaura.github.io)와 별개로 개발 기록을 남길 공간이 필요했다. GitHub는 계정당 User Pages를 1개만 허용하지만 Project Pages는 제한이 없다. 새 저장소 하나로 두 번째 블로그를 세운 과정을 정리한다.

왜 저장소를 나눴나

선택지는 네 가지였다.

방식주소장점단점
별도 저장소/devblog/글 목록·RSS·태그 완전 분리, 기존 블로그 무손상URL 두 개
기존 저장소 서브디렉터리/dev/인프라 공유, URL 하나빌드 스크립트를 2개 컬렉션 지원으로 개조해야 함
태그만 추가동일즉시 가능투자 독자와 개발 독자가 섞임
커스텀 도메인dev.example.com가장 깔끔도메인 비용·DNS 설정

기존 블로그에 이미 50편 넘는 글이 쌓여 있었다. 빌드 스크립트를 건드려 그걸 깨뜨릴 위험을 감수할 이유가 없어서 별도 저장소를 골랐다. RSS 구독자도 관심사별로 나뉜다.

서브패스 배포에서 깨지는 것

User Pages는 루트(/)에 배포되지만 Project Pages는 /저장소이름/ 아래에 배포된다. 기존 코드를 그대로 복사하면 모든 절대경로가 404가 된다.

깨지는 예 — 루트 기준 절대경로
<link rel="stylesheet" href="/assets/style.css">
<a href="/posts/hello.html">글</a>
<!-- 실제 파일은 /devblog/assets/style.css 에 있다 -->

해결은 BASE 상수를 두고 빌드 시점에 주입하는 것이다. 상대경로(../assets/)를 쓰면 목록 페이지와 글 페이지의 깊이가 달라 관리가 더 번거로워진다.

build.py
import json, pathlib

data = json.loads((ROOT / "posts.json").read_text(encoding="utf-8"))
site = data["site"]
BASE = site.get("base", "/devblog").rstrip("/")

# 모든 링크 생성부에서 BASE 를 앞에 붙인다
card = f'<a class="card" href="{BASE}/posts/{slug}.html">'

추가로 .nojekyll 빈 파일을 루트에 둔다. 없으면 GitHub Pages가 Jekyll 파이프라인을 태우면서 언더스코어로 시작하는 디렉터리를 무시한다.

코드블록 하이라이팅 구성

투자 블로그 CSS에는 <pre> 스타일이 아예 없었다. 개발 블로그에서는 이게 본문의 절반이라 새로 짜야 했다.

highlight.js는 보통 테마 CSS를 하나 골라 로드하는데, 그러면 다크모드 전환 시 코드블록만 색이 안 바뀐다. 테마 CSS를 안 쓰고 토큰 클래스를 직접 CSS 변수로 칠하면 이 문제가 사라진다.

assets/style.css
:root {
  --c-key: #a626a4;  --c-str: #0a7d38;
  --c-num: #b76b01;  --c-com: #8b939c;
}
[data-theme="dark"] {
  --c-key: #ff7b72;  --c-str: #7ee787;
  --c-num: #ffa657;  --c-com: #6e7781;
}

.hljs-keyword { color: var(--c-key); }
.hljs-string  { color: var(--c-str); }
.hljs-number  { color: var(--c-num); }
.hljs-comment { color: var(--c-com); font-style: italic; }

번들도 CDN 대신 저장소에 직접 넣었다. 코어 + 실제로 쓰는 언어 33종만 esbuild로 묶으면 132KB, CDN 장애·차단에 영향받지 않는다.

tools/template.html
<script src="/devblog/assets/hljs.min.js"></script>
<script>if(window.hljs){hljs.highlightAll();}</script>
모바일에서 자주 깨지는 지점 — 긴 코드 한 줄이 화면을 밀어내면 페이지 전체에 가로 스크롤이 생기고 본문 좌우 여백까지 무너진다. pre 에 overflow-x: auto 를 주고, 표는 <div class="table-wrap"> 로 감싸는 것이 최소 조건이다.

발행 절차

  1. GitHub에서 빈 public 저장소 devblog 생성 (README 체크 해제)
  2. 빌드 스크립트·템플릿·CSS를 넣고 첫 커밋 push
  3. Settings → Pages → Source를 main 브랜치 루트로 지정
  4. 1~2분 뒤 https://사용자명.github.io/devblog/ 확인

이후 글 발행은 명령 한 줄이다.

terminal
export GITHUB_TOKEN=github_pat_...

python3 publish.py \
  --title "Kotlin Flow 디바운스 처리" \
  --tags "Android,Kotlin,튜토리얼" \
  --summary "검색어 입력에 debounce 300ms 적용해 API 호출을 1/8로 줄인 과정" \
  --slug "2026-08-12-kotlin-flow-debounce" \
  --body body.html

스크립트가 템플릿 적용 → posts.json 갱신 → index.html·sitemap.xml·rss.xml 재생성 → commit → push를 순서대로 처리한다.

토큰 권한 주의 — fine-grained PAT는 기존 저장소에 admin 권한이 있어도 새 저장소 생성 권한은 별도다. API로 저장소를 만들려면 계정 수준 Administration 권한이 필요하고, 없으면 웹에서 한 번 만들어주는 편이 빠르다.
