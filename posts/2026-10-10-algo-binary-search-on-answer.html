일직선 위의 이물질을 최대 uses번의 장비 사용으로 모두 덮을 때 필요한 최소 흡입력 V를 구하는 문제다. "최소 V가 얼마인가"를 직접 구하기는 어렵지만, "V가 이 값이면 가능한가"는 왼쪽부터 덮어 나가는 그리디로 쉽게 판정된다. V가 커질수록 가능해지기만 하므로, 판정 함수를 이분 탐색으로 감싸면 가능과 불가능의 경계가 곧 답이다. 학습 교재 09단원 예제 코드를 추적한 기록이며, 장비 중심 위치까지 구하는 변형을 덧붙였다 (Python 3 실행 확인).

문제

일직선 위에 이물질이 놓여 있다. 장비를 중심 x에서 한 번 사용하면 구간 [x − V, x + V]의 이물질이 제거된다. 양 끝을 포함한다.

  • 입력: points — 비어 있지 않은 음이 아닌 좌표 리스트. 정렬되어 있지 않을 수 있다. uses — 1 이상의 최대 사용 횟수.
  • 흡입력 V는 모든 사용에서 같고, 음이 아닌 정수다.
  • 중심은 이물질 위치가 아니어도 된다.
  • 장비를 uses번보다 적게 써도 된다.
  • 출력: 모든 이물질을 덮을 수 있는 최소 V.
pointsuses출력이유
[1, 3, 8, 10, 18, 20, 25]25중심 6이 1 ~ 11, 중심 23이 18 ~ 28을 덮는다
[0, 3]12간격 3을 정수 V로 덮으려면 2V ≥ 3
[10, 0, 5]30이물질마다 한 번씩 쓰면 V = 0으로 충분
[0, 1000000000]1500000000양 끝의 한가운데에 중심

전체 코드

minimum_power.py
def minimum_power(points, uses):
    points = sorted(points)

    def possible(power):
        count = 0
        covered_until = -1
        for point in points:
            if point <= covered_until:
                continue
            count += 1
            if count > uses:
                return False
            covered_until = point + 2 * power
        return True

    low = 0
    high = (points[-1] - points[0] + 1) // 2
    while low < high:
        mid = (low + high) // 2
        if possible(mid):
            high = mid
        else:
            low = mid + 1
    return low


def run_checks():
    assert minimum_power([1, 3, 8, 10, 18, 20, 25], 2) == 5
    assert minimum_power([0, 3], 1) == 2
    assert minimum_power([10, 0, 5], 3) == 0
    assert minimum_power([0, 1000000000], 1) == 500000000
    print("09단원: 확인용 테스트 4개 통과")


if __name__ == "__main__":
    run_checks()

핵심 아이디어

문제를 두 겹으로 나눈다.

  1. 최적화 문제를 판정 문제로 바꾼다 — "최소 V는?" 대신 "V가 주어지면 uses번 안에 다 덮을 수 있나?"를 묻는다. 답은 예/아니오다.
  2. 판정 결과가 한 방향으로만 바뀐다 — V로 가능하면 V + 1로도 가능하다(같은 중심에서 더 넓게 덮을 뿐이다). 따라서 V를 0부터 늘려 가면 결과가 "불가능 … 불가능, 가능 … 가능"으로 딱 한 번 바뀐다.
  3. 바뀌는 지점을 이분 탐색으로 찾는다 — 첫 번째 "가능"이 최소 V다.
V        0   1   2   3   4   5   6   7  ...  12
가능?    X   X   X   X   X   O   O   O  ...   O
                             ^
                          최소 V = 5
판별 기준 — "조건을 만족하는 최솟값(최댓값)을 구하라"에서 값을 직접 계산하는 식이 떠오르지 않으면 두 가지를 확인한다. 값을 하나 정했을 때 가능 여부를 빠르게 판정할 수 있는가. 그리고 값이 커질수록 가능 여부가 한 방향으로만 바뀌는가. 둘 다 예라면 답에 대한 이분 탐색이다.

판정 함수 possible

def possible(power):
    count = 0
    covered_until = -1
    for point in points:
        if point <= covered_until:
            continue
        count += 1
        if count > uses:
            return False
        covered_until = point + 2 * power
    return True

V가 정해졌을 때 필요한 최소 사용 횟수를 세는 그리디다. 정렬된 점을 왼쪽부터 본다.

  • 아직 덮이지 않은 가장 왼쪽 점을 만나면 장비를 한 번 쓴다.
  • 그 점을 구간의 왼쪽 끝에 맞춘다. 중심은 point + V, 덮는 범위는 [point, point + 2V]다.
  • 범위 안의 점은 건너뛰고, 범위를 벗어난 첫 점에서 다시 한 번 쓴다.
point          point + V        point + 2V
  |----------------x----------------|
 왼쪽 끝          중심            오른쪽 끝 (covered_until)

왼쪽 끝에 맞추는 것이 최선인 이유는 단순하다. 가장 왼쪽 점은 어차피 덮어야 하고, 그보다 왼쪽에는 덮을 것이 없다. 구간을 더 왼쪽으로 밀면 빈 곳을 덮느라 오른쪽을 손해 보고, 더 오른쪽으로 밀면 그 점을 놓친다.

covered_until의 초기값 -1은 "아직 아무것도 덮지 않았다"는 뜻이다. 좌표가 음이 아니므로 첫 점은 항상 미덮임으로 판정된다. 횟수가 uses를 넘는 즉시 False를 반환해 남은 점을 보지 않는다.

이분 탐색 틀

low = 0
high = (points[-1] - points[0] + 1) // 2
while low < high:
    mid = (low + high) // 2
    if possible(mid):
        high = mid
    else:
        low = mid + 1
return low
요소값근거
low 초기값0V는 음이 아닌 정수
high 초기값(최대 − 최소 + 1) // 2전체 폭의 절반을 올림한 값. 한 번만 써도 전부 덮이므로 항상 가능한 값이다
가능하면high = midmid가 답일 수 있으므로 버리지 않는다
불가능하면low = mid + 1mid 이하는 전부 불가능하다
종료low == high후보가 하나 남았고 그것이 답

반복 내내 "답은 low 이상 high 이하이고, high는 항상 가능한 값"이라는 조건이 유지된다. 그래서 끝난 뒤 low를 다시 판정할 필요가 없다. 대신 high의 초기값이 정말 가능한 값이어야 한다.

판정 함수는 4번 호출됐다. V = 4에서는 첫 구간이 9까지만 닿아 10을 놓치고, V = 5가 되어야 11까지 닿아 1, 3, 8, 10이 한 번에 덮인다.

놓치기 쉬운 함정

실수입력잘못된 결과기대값
중심을 이물질 위에 둠 (point + power)첫 번째 예제95
경계 미포함 (point < covered_until)[0, 2, 4], 221

정렬 생략[10, 0, 5], 105

네 줄 모두 잘못 짠 코드를 실행해 얻은 값이다.

1. 중심은 이물질 위치가 아니어도 된다

가장 왼쪽 이물질 위에 중심을 두면 구간의 왼쪽 절반이 빈 곳을 덮는다. 덮는 범위가 point + V까지로 줄어 필요한 V가 거의 두 배가 된다. 이물질을 구간의 왼쪽 끝에 맞추므로 2 * power다.

2. 양 끝을 포함한다

[0, 2, 4], 2번 사용에서 V = 1이면 [0, 2]와 [4, 6]으로 충분하다. 비교를 <로 쓰면 정확히 끝에 걸친 2를 못 덮은 것으로 처리해 V = 1을 불가능으로 판정한다.

3. 상한은 반드시 "가능한 값"이어야 한다

폭이 홀수일 때 내림하면 그 값으로는 전체를 덮지 못한다. [0, 3]에서 high를 1로 잡으면 반복문은 1을 검증 없이 답으로 돌려준다. 이 틀은 high를 한 번도 판정하지 않고 믿기 때문에, 상한 계산의 올림 여부가 그대로 정답에 반영된다.

4. 정렬을 빼먹는다

왼쪽부터 덮는 그리디와 points[-1] - points[0] 상한 모두 정렬을 전제로 한다. 입력이 정렬되어 있다는 보장이 없으므로 함수 첫 줄에서 정렬한다. 문제 조건으로 정렬이 금지되지 않았는지도 확인한다. 이 문제는 위치만 의미가 있고 입력 순서는 의미가 없다.

5. 갱신식을 섞어 쓰면 끝나지 않는다

조합결과
mid 내림 + high = mid + low = mid + 1정상. 최솟값 찾기 (이 코드)
mid 내림 + low = midlow와 high가 1 차이일 때 mid == low가 되어 무한 반복
mid 올림 + low = mid + high = mid - 1정상. 최댓값 찾기에 쓰는 대칭형

구간이 매번 반드시 줄어드는지를 low와 high가 붙어 있는 경우로 확인하면 된다.

6. V를 0부터 하나씩 올려 본다

판정 함수가 있으니 선형으로 올려도 답은 나온다. 하지만 마지막 예제는 답이 5억이라 판정을 5억 번 넘게 호출해야 한다. 이분 탐색은 같은 입력에서 판정을 28번 호출했다(실행해서 센 값). 좌표 범위가 두 배가 되어도 호출은 한 번 늘 뿐이다.

변형: 장비 중심 위치까지

교재 범위를 넘어 직접 추가한 변형이다. 최소 V를 구한 뒤 판정 함수와 같은 순회를 한 번 더 하면서 중심을 기록하면 실제 배치가 나온다.

cleaning_plan.py
def cleaning_plan(points, uses):
    power = minimum_power(points, uses)
    centers = []
    covered_until = -1
    for point in sorted(points):
        if point <= covered_until:
            continue
        centers.append(point + power)
        covered_until = point + 2 * power
    return power, centers


print(cleaning_plan([1, 3, 8, 10, 18, 20, 25], 2))  # (5, [6, 23])
print(cleaning_plan([1, 3, 8, 10, 18, 20, 25], 3))  # (4, [5, 14, 24])
print(cleaning_plan([0, 3], 1))                     # (2, [2])

최소 V를 만드는 배치는 여러 개일 수 있고, 이 코드는 그중 구간을 가능한 한 왼쪽 이물질에 붙인 배치 하나를 돌려준다.

검증에는 이분 탐색도 그리디도 쓰지 않는 구현을 따로 만들었다. 정렬한 점을 연속한 묶음으로 나누는 모든 방법을 동적 계획법으로 탐색해, 묶음별 필요 V(폭의 절반 올림)의 최댓값이 가장 작은 경우를 찾는 방식이다.

최소 V 대조점 1 ~ 8개, 좌표 0 ~ 40, 사용 1 ~ 5번, 무작위 10만 건전부 일치
배치 검사중심 개수가 uses 이하, 모든 점이 어떤 중심에서 V 이내전부 통과
