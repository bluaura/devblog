Ghidra는 미국 NSA가 만든 무료 오픈소스 리버스 엔지니어링(SRE) 프레임워크다. 바이너리를 디스어셈블하고 C에 가까운 의사코드로 디컴파일해 준다. 상용 IDA Pro의 대안으로 가장 많이 쓰인다. 핵심 판단 기준은 하나다. C/C++/Rust/Go/Swift처럼 네이티브로 컴파일된 코드면 Ghidra, Java·.NET·JS처럼 바이트코드나 스크립트면 전용 디컴파일러가 먼저다.

참고 — GitHub 메인 브랜치 README는 JDK 25를 요구한다. 이건 다음 개발 버전 기준이고, 12.x 릴리스는 JDK 21로 동작한다.

연혁

  • 개발은 1999년경 시작된 것으로 추정된다(소스 주석 근거).
  • 2017년 3월 WikiLeaks의 Vault 7 유출로 존재가 알려졌다.
  • 2019년 3월 RSA 컨퍼런스에서 9.0이 공개됐고, 약 한 달 뒤 GitHub에 소스가 올라왔다.
  • 10.0(2021): 디버거 추가
  • 11.0(2023): Rust/Go 바이너리 지원, BSim
  • 11.1(2024): Swift, DWARF 5, Mach-O 개선
  • 12.0: PyGhidra가 기본 Python 엔진이 됨
  • 12.1: 비트필드 복원, Objective-C 분석기 교체

주요 기능

  • 디스어셈블과 디컴파일: x86/x64, ARM/AArch64, MIPS, PowerPC, RISC-V 등 수십 개 프로세서를 지원한다. 프로세서 정의는 SLEIGH 언어로 작성하므로 새 아키텍처를 직접 추가할 수 있다.
  • 실행 파일 포맷: PE(EXE/DLL), ELF(실행 파일/.so), Mach-O(dylib/framework), Android DEX 등. DLL과 공유 라이브러리도 문제없이 분석한다.
  • 스크립팅: Java 또는 Python. 12.0부터 Python 기본 엔진이 Jython에서 PyGhidra(CPython 3)로 바뀌었다.
  • 헤드리스 모드: analyzeHeadless로 GUI 없이 일괄 분석. CI나 자동화, AI 에이전트 연동에 쓴다.
  • 디버거: Windows는 WinDbg, Linux는 GDB, macOS는 LLDB와 연동. 12.0부터 Z3 기반 심볼릭(concolic) 에뮬레이터가 실험적으로 들어갔다.
  • 협업: Ghidra Server로 여러 명이 같은 프로젝트를 버전 관리하며 분석할 수 있다.
  • Version Tracking / BSim: 두 빌드 사이의 함수 대응과 변경점을 찾고, 유사 함수를 검색한다. 패치 diff 분석에 유용하다.

12.x 주요 변경점

버전변경 내용
12.0PyGhidra 3.0이 기본이 되면서 Jython 스크립트는 # @runtime Jython 헤더가 필요해짐. 데이터 참조 그래프(Ctrl+G) 추가. RISC-V/NDS32 추가
12.1Jython 기본 번들 제외(확장으로 별도 설치). 디컴파일러가 구조체 비트필드 이름을 복원. objc_msgSend 호출을 실제 메서드로 해석. debuginfod로 DWARF 자동 다운로드. Hexagon 프로세서 추가. Ghidra Server 보안 강화
호환성 주의 — 12.x에서 만들거나 수정한 프로젝트는 이전 버전에서 열 수 없다. Ghidra Server를 쓴다면 서버와 클라이언트 버전도 맞춰야 한다.

AI·에이전트 연동

Ghidra 공식 릴리스에는 MCP나 AI 기능이 없다. 대신 서드파티 MCP 서버가 여럿 있다.

  • GhidraMCP (LaurieWired): GUI 플러그인 방식. 가장 많이 알려진 프로젝트
  • pyghidra-mcp: 헤드리스, PyGhidra 기반
  • REA: Ghidra·Hopper·IDA를 엔진으로 골라 쓰는 리버스 엔지니어링 MCP. 이전 글에서 정리했다.

설치와 실행

  1. GitHub Releases에서 ghidra_12.1.4_PUBLIC zip을 받아 압축을 푼다. 별도 설치 과정은 없다.
  2. 64비트 JDK 21을 설치한다.
  3. 아래 명령으로 실행한다.
terminal
# GUI 실행 (Windows: ghidraRun.bat)
./ghidraRun

# 헤드리스: 바이너리를 임포트하고 자동 분석 후 프로젝트 삭제
./support/analyzeHeadless /tmp/proj MyProj -import ./target.dll -deleteProject

# PyGhidra(Python 3) 실행
./support/pyghidraRun

언제 쓰면 좋은가 — 활용 사례 8가지

공통점은 "소스코드는 없고 바이너리만 있는데, 그 안에서 실제로 무슨 일이 일어나는지 확인해야 할 때"다.

1. 자사 제품의 문제 해결

  • 릴리스 빌드 크래시 추적: 심볼 없는 Windows 크래시 덤프나 Android 네이티브 툼스톤에 찍힌 오프셋을 Ghidra에서 열면, 해당 주소가 어떤 함수의 어느 분기인지 의사코드로 바로 보인다. PDB나 DWARF가 있으면 함수명까지 복원된다.
  • 빌드 간 차이 검증: 버전 A와 B의 바이너리를 Version Tracking으로 비교한다. "소스는 안 바꿨는데 동작이 달라졌다"는 컴파일러·링커·의존성 변경 이슈를 확인할 때 쓴다.
  • 소스 유실 레거시 모듈 유지보수: 퇴사자가 남긴 DLL이나 외주 납품 바이너리처럼 소스가 없는 모듈의 동작을 복원해 재작성 근거로 삼는다.

2. 서드파티 SDK·라이브러리 검증

  • 문서에 없는 동작 확인: 벤더 SDK가 내부적으로 어떤 시스템 API를 호출하는지, 타임아웃이나 재시도 값이 하드코딩돼 있는지 확인한다. BLE·WiFi 칩셋 SDK처럼 문서가 부실한 경우에 특히 유용하다.
  • 취약 라이브러리 내장 여부 점검: BSim으로 바이너리 안에 구버전 OpenSSL이나 zlib 함수가 정적 링크돼 있는지 찾는다. SBOM에 안 잡히는 공급망 리스크 점검에 쓴다.
  • 개인정보·네트워크 동작 감사: 광고·분석 SDK가 어떤 데이터를 어디로 보내는지 문자열과 호출 흐름으로 확인한다.

3. 보안 패치 분석 (Patch Diffing)

  • Windows Patch Tuesday처럼 패치 전후 바이너리를 비교해 수정된 함수를 찾고, 취약점의 근본 원인을 파악한다.
  • 도구로는 Ghidriff(Ghidra 기반 CLI 바이너리 diff)가 있다. 명령 한 번으로 변경 함수 목록을 마크다운 리포트로 뽑아준다(SecTor 2023 발표).
  • 활용 시점: 자사 앱이 의존하는 OS 컴포넌트나 라이브러리에 CVE가 발표됐을 때, 영향 범위를 직접 판단해야 하는 경우

4. 악성코드·의심 파일 분석

  • 보안 업계에서 Ghidra를 가장 많이 쓰는 분야다. 의심 실행 파일을 실행하지 않고 정적으로 문자열, C2 주소, 암호화 루틴을 추출한다.
  • 활용 시점: 고객이 "앱 설치 후 이상한 파일이 생겼다"고 제보하거나, 사내에서 출처 불명 바이너리를 발견했을 때
주의 — 의심 파일은 반드시 격리된 VM에서 다룬다.

5. 펌웨어·임베디드 분석

  • 공유기, IoT 기기, 주변기기의 펌웨어를 Binwalk로 추출한 뒤 Ghidra로 분석한다. ARM, MIPS, RISC-V 등 임베디드 프로세서 지원이 강점이다.
  • 활용 시점: 연동 대상 하드웨어(디스플레이, 동글 등)의 통신 프로토콜을 파악할 때, 협력사 펌웨어의 보안 검수를 할 때
  • Black Hat에서 "Reverse Engineering Firmware with Ghidra" 정규 교육 과정이 운영될 정도로 표준 도구로 자리 잡았다.

6. 파일 포맷·프로토콜 상호운용성

  • 독점 파일 포맷(설정 파일, 저장 데이터)이나 통신 프로토콜의 파서 함수를 분석해 구조를 복원한다. 레거시 시스템과의 연동이나 데이터 마이그레이션에 쓴다.
  • 활용 시점: 단종된 제품의 데이터를 새 앱으로 옮겨야 하는데 포맷 문서가 없을 때

7. 게임·소프트웨어 보존 (디컴파일 프로젝트)

  • N64 Super Mario 64 디컴파일 프로젝트가 대표 사례다. ROM을 다시 컴파일 가능한 C 코드로 복원해 해상도 제한 없는 네이티브 PC 포트까지 나왔다. Ghidra는 MIPS를 지원하고 상당 부분을 자동화할 수 있어 이런 프로젝트에 쓰였다.
  • AI 결합 사례: GBA 소닉 어드밴스 3 디컴파일에서 DeepSeek R1이 함수 단위로 약 60~74% 일치 코드를 생성했고, 일부는 수정 후 100% 일치를 달성했다. 작성자는 다음 단계로 GhidraMCP 같은 MCP 연동을 꼽았다.

8. 학습·역량 개발

  • 어셈블리와 컴파일러 동작 학습: 직접 짠 C/C++/Kotlin Native 코드를 빌드해 Ghidra로 열어보면 최적화 옵션별로 기계어가 어떻게 달라지는지 체감할 수 있다. 성능 튜닝에 도움이 된다.
  • CTF·보안 교육: 리버싱 문제 풀이의 기본 도구다. 팀 역량 개발 과제로도 쓸 만하다.
