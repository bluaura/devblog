문제

지점 사이의 거리가 행렬로 주어진다. 0번에서 출발해 나머지 지점을 한 번씩 방문하고 0번으로 돌아온다. 방문 순서를 자유롭게 정해 총 거리를 최소화한다.

  • 입력: distance — 작은 N×N 거리 행렬. distance[i][j]는 i에서 j로 가는 거리다. 대각선은 0이고 모든 지점에 도달할 수 있다.
  • 출력: 복귀까지 포함한 최소 전체 거리. 지점이 0번 하나뿐이면 0이다.
  • 행렬은 대칭이 아닐 수 있다. i에서 j로 가는 거리와 j에서 i로 가는 거리가 다를 수 있다.
distance출력최단 순회
[[0, 2, 3], [2, 0, 4], [3, 4, 0]]90 → 1 → 2 → 0: 2 + 4 + 3
[[0, 5], [5, 0]]100 → 1 → 0: 5 + 5
[[0]]0방문할 곳이 없다
[[0, 1, 10], [10, 0, 1], [1, 10, 0]]30 → 1 → 2 → 0: 1 + 1 + 1 (반대 방향은 30)

전체 코드

shortest_tour.py
from itertools import permutations


def shortest_tour(distance):
    targets = range(1, len(distance))
    best = float('inf')
    for order in permutations(targets):
        previous = 0
        total = 0
        for current in order:
            total += distance[previous][current]
            previous = current
        total += distance[previous][0]
        best = min(best, total)
    return best


def run_checks():
    assert shortest_tour([[0, 2, 3], [2, 0, 4], [3, 4, 0]]) == 9
    assert shortest_tour([[0, 5], [5, 0]]) == 10
    assert shortest_tour([[0]]) == 0
    assert shortest_tour([[0, 1, 10], [10, 0, 1], [1, 10, 0]]) == 3
    print("10단원: 확인용 테스트 4개 통과")


if __name__ == "__main__":
    run_checks()

핵심 아이디어

  1. 정해야 하는 것은 순서뿐이다 — 출발과 도착은 0번으로 고정이고, 나머지 지점은 전부 한 번씩 들러야 한다. 선택의 여지가 있는 것은 "어떤 순서로 들를까" 하나다.
  2. 순서를 전부 나열한다 — 1번부터 N−1번까지를 일렬로 세우는 방법은 (N−1)!가지다. 0번은 고정이므로 순열에 넣지 않는다.
  3. 순서마다 길이를 잰다 — 0번에서 시작해 순서대로 이동 거리를 더하고, 마지막 지점에서 0번으로 돌아오는 거리를 더한다.
  4. 최솟값을 남긴다.
판별 기준 — "모든 지점을 한 번씩 방문하는 최단 순서"는 외판원 문제로, 순서를 빠르게 정하는 규칙이 알려져 있지 않다. 입력 제한에서 지점 수가 10개 안팎으로 작게 주어졌다면 순열 완전 탐색을 의도한 문제다. 제한이 작다는 것 자체가 힌트다.

코드 한 줄씩 보기

순열 대상은 1번부터

targets = range(1, len(distance))
for order in permutations(targets):

permutations는 주어진 원소를 일렬로 세우는 모든 방법을 튜플로 하나씩 내준다. 지점이 4개면 (1, 2, 3), (1, 3, 2), (2, 1, 3) … 여섯 개다. 리스트로 한꺼번에 만들지 않고 하나씩 생성하므로 메모리는 순열 하나 크기만 쓴다.

직전 지점을 들고 다니며 더한다

previous = 0
total = 0
for current in order:
    total += distance[previous][current]
    previous = current

previous를 0으로 시작하는 것이 "0번에서 출발"이다. 인덱스 순서는 [출발][도착]이다.

복귀 거리

total += distance[previous][0]
best = min(best, total)

반복문이 끝났을 때 previous는 마지막으로 방문한 지점이다. 거기서 0번으로 돌아오는 거리를 더해야 순회가 완성된다.

지점이 하나뿐일 때

range(1, 1)은 비어 있다. 빈 대상의 순열은 "없음"이 아니라 빈 튜플 하나다. 실행해 보면 list(permutations(range(1, 1)))은 [()]이다. 그래서 바깥 반복문이 한 번 돌고, 안쪽 반복문은 돌지 않으며, distance[0][0]인 0이 더해져 답이 0이 된다. 별도 분기 없이 처리된다.

세 줄 모두 잘못 짠 코드를 실행해 얻은 값이다.

1. 돌아오는 구간을 빼먹는다

반복문은 "다음 지점으로 가는 거리"만 더한다. 마지막 지점에서 0번으로 돌아오는 구간은 반복문 밖에서 따로 더해야 한다. 문제가 "복귀까지 포함"인지 "마지막 지점에서 끝"인지에 따라 이 한 줄의 유무가 갈린다.

2. 가까운 곳부터 가면 된다고 생각한다

매번 가장 가까운 미방문 지점으로 가는 방법은 위 예제에서 0 → 1 → 3 → 2 → 0을 골라 33이 나온다. 초반에 아낀 거리를 마지막 구간(2 → 0, 거리 15)에서 전부 잃는다. 전체를 봐야 알 수 있는 손해라서 한 걸음씩 최선을 고르는 방식으로는 피할 수 없다.

3. 대칭이라고 가정한다

거리가 대칭이면 어떤 순서와 그 역순의 길이가 같으므로 절반만 봐도 된다. 하지만 이 문제의 행렬은 대칭이 보장되지 않는다. 표의 세 번째 줄은 한 방향이 3, 반대 방향이 30인 경우로, 역순을 건너뛰면 30을 답으로 낸다. 최적화는 문제 조건을 확인한 뒤에 넣는다.

4. 0번까지 순열에 넣는다

permutations(range(len(distance)))로 쓰면 시도 횟수가 N!로 늘어난다. 순회는 어디서 시작하든 같은 고리이므로 출발점을 고정해도 잃는 것이 없다. N = 10이면 10배 차이다.

5. 최솟값 초기값

best를 0으로 두면 어떤 합계도 0보다 작지 않아 항상 0이 나온다. 최솟값을 찾을 때는 무한대로 시작한다.

규모의 한계와 비트마스크 DP

순열의 수는 지점이 하나 늘 때마다 곱으로 불어난다.

실행 시간은 한 번 측정한 값이라 환경에 따라 달라진다. N이 하나 늘 때 완전 탐색 시간이 약 10배씩 커지는 추세만 참고한다. 이 추세라면 N = 12는 십수 초, N = 13은 분 단위가 된다.

교재 범위를 넘어 직접 추가한 코드다. 순열 완전 탐색이 느린 이유는 같은 계산을 반복하기 때문이다. "1, 2, 3번을 방문하고 지금 3번에 있다"는 상황에서 앞으로의 최선은 1과 2를 어떤 순서로 들렀는지와 무관하다. 그러니 (방문한 지점 집합, 현재 위치)마다 최소 거리 하나만 기억하면 된다.

shortest_tour_dp.py
def shortest_tour_dp(distance):
    n = len(distance)
    if n == 1:
        return 0
    full = 1 << (n - 1)                 # 0번을 제외한 지점들의 방문 집합
    INF = float('inf')
    best = [[INF] * (n - 1) for _ in range(full)]
    for last in range(n - 1):
        best[1 << last][last] = distance[0][last + 1]
    for visited in range(1, full):
        for last in range(n - 1):
            current = best[visited][last]
            if current == INF:
                continue
            for nxt in range(n - 1):
                if visited & (1 << nxt):
                    continue
                candidate = current + distance[last + 1][nxt + 1]
                if candidate < best[visited | (1 << nxt)][nxt]:
                    best[visited | (1 << nxt)][nxt] = candidate
    return min(best[full - 1][last] + distance[last + 1][0] for last in range(n - 1))
  • 집합을 정수 하나로 표현한다. k번 지점을 방문했으면 (k − 1)번째 비트를 1로 둔다. 0번은 항상 출발점이라 비트를 쓰지 않는다. 그래서 코드에서 비트 번호와 지점 번호가 1씩 어긋난다(last + 1).
  • best[visited][last]는 0번에서 출발해 visited에 든 지점을 모두 들르고 last에 서 있을 때의 최소 거리다.
  • visited를 작은 수부터 처리해도 되는 이유는 지점을 하나 추가하면 정수 값이 반드시 커지기 때문이다. 필요한 값이 항상 먼저 계산되어 있다.
  • 마지막에 모든 지점을 방문한 상태(full - 1)에서 각 위치의 값에 복귀 거리를 더해 최솟값을 고른다.

두 구현의 결과가 같은지 지점 1 ~ 8개 무작위 비대칭 행렬 3,000건과 위 표의 N = 9, 10, 11 입력에서 확인했다. 전부 일치했다.

앞 단계: BFS로 거리 행렬 만들기

문제 설명에 따르면 실제 문제는 장애물이 있는 지도에서 시작하고, 지점 사이의 거리를 구하는 것은 별도의 BFS 단계다. 직접 추가한 코드로 두 단계를 이어 본다. 05단원의 격자 BFS를 지점마다 한 번씩 돌려 행렬의 한 행을 채운다.

distance_matrix.py
from collections import deque


def distance_matrix(grid, spots):
    rows, columns = len(grid), len(grid[0])
    matrix = []
    for sr, sc in spots:
        dist = [[-1] * columns for _ in range(rows)]
        dist[sr][sc] = 0
        queue = deque([(sr, sc)])
        while queue:
            r, c = queue.popleft()
            for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
                nr, nc = r + dr, c + dc
                if not (0 <= nr < rows and 0 <= nc < columns):
                    continue
                if grid[nr][nc] == 1 or dist[nr][nc] != -1:
                    continue
                dist[nr][nc] = dist[r][c] + 1
                queue.append((nr, nc))
        matrix.append([dist[r][c] for r, c in spots])
    return matrix


grid = [[0, 0, 0, 1],
        [1, 1, 0, 1],
        [0, 0, 0, 0],
        [0, 1, 1, 0]]
spots = [(0, 0), (2, 0), (3, 3), (0, 2)]   # 0번이 출발점

matrix = distance_matrix(grid, spots)
print(matrix)                 # [[0, 6, 6, 2], [6, 0, 4, 4], [6, 4, 0, 4], [2, 4, 4, 0]]
print(shortest_tour(matrix))  # 16

BFS는 도착점에서 멈추지 않고 격자 전체의 거리를 구한 뒤, 필요한 지점의 값만 뽑는다. 지점 쌍마다 BFS를 돌리는 것보다 횟수가 적다(지점 수만큼만 돈다). 도달할 수 없는 지점이 있으면 행렬에 -1이 들어가 합계가 틀어지므로, 그런 입력이 가능한 문제라면 순회 계산 전에 -1을 검사해야 한다. 이 단원의 문제는 모든 지점에 도달 가능하다고 보장한다.
