Hermes Agent는 Nous Research가 2026년 3월 공개한 MIT 오픈소스 셀프호스팅 AI 에이전트다. IDE 코딩 도우미가 아니라 "24시간 돌아가면서 기억과 스킬이 쌓이는 개인 비서"를 지향하며, Telegram·Discord·Slack 등 20여 개 메신저를 하나의 게이트웨이로 묶는다. 플러그인 API가 잘 정리되어 있어 앱 개발자가 자기 앱을 에이전트의 손발로 연결하기 좋은 구조다. 단, 운영 규율(상시 가동·샌드박스·비용)이 없으면 장점이 나오지 않는다는 것이 후기의 공통점이다.

Hermes Agent란

Nous Research(Hermes 모델 시리즈로 알려진 오픈소스 AI 연구 조직)가 만든 자율 에이전트 런타임이다. 저장소는 2025년 7월에 만들어졌고 2026년 2월 말 공개 전환, 3월 12일 정식 런칭했다. 공개 후 50일 동안 6번의 정식 릴리즈를 냈고, 9월 현재 GitHub 240k 스타·49k 포크·300명 이상의 기여자를 기록 중이다.

공식 문서가 스스로를 정의하는 문장은 명확하다. "IDE에 묶인 코딩 코파일럿도, 단일 API를 감싼 챗봇 래퍼도 아니다. 오래 돌릴수록 더 유능해지는 자율 에이전트다." 핵심은 세 가지다.

  • 학습 루프 — 복잡한 작업을 끝내면 에이전트가 스스로 SKILL.md를 작성해 다음에 재사용하고, 쓰면서 개선한다.
  • 영속 메모리 — MEMORY.md / USER.md 노트 + SQLite FTS5 전체 세션 검색 + (선택) Honcho 기반 사용자 모델링.
  • 어디서나 접근 — CLI, 메신저 20여 종, IDE(ACP), 데스크톱 앱, 음성까지 하나의 세션 상태를 공유한다.

사용자 리뷰와 후기

긍정

  • 홈랩 운영자: "내 홈랩의 sysadmin이다. 마법 같다." 상태가 유지되는 유능한 에이전트를 갖는 것 자체가 체감 가치라는 평이 많다.
  • Mac mini M4에서 30일 운영한 국내 블로거: 재사용 스킬이 3개에서 19개로 늘었고, 반복 작업 응답 시간이 47초에서 11초로 줄었다. 3주차부터는 "주간 리포트, 평소 형식"이라고만 쳐도 되묻지 않고 처리했다.
  • 비용 절감 사례: 월 80~150달러짜리 상용 구성을 10달러 Hetzner VPS + 모델 선택으로 대체. 스크립트 모드로 돌리면 토큰이 0이라는 발견도 있다.
  • 공식 User Stories 326건 중 개발 워크플로(77), 개인 비서(49), 통합 확장(32), 창작(26), 비즈니스 운영(23) 순으로 많다.

부정·주의

  • UX: 초기 버전은 "시작이 굼뜨고 CLI가 깜빡거리며 지나치게 장황하다"는 지적. v0.19에서 콜드스타트 80% 단축으로 상당 부분 개선됐다고 릴리즈 노트는 주장한다.
  • 운영 규율: "메모리가 영속된다"와 "서비스가 살아 있다"는 다르다. 30일 후기에서 38시간 다운타임 동안 승인 워크플로가 끊겼고, Raspberry Pi 4B는 SQLite I/O 병목으로 3일 만에 포기했다. 30일에 디스크 2.3GB가 쌓여 백업 자동화가 필수였다.
  • 실질 비용: eesel의 계산기는 VPS 20달러 + API 60달러 + 주 3.5시간 유지보수 인건비를 합쳐 월 535달러 수준으로 본다. 소프트웨어는 공짜지만 운영은 공짜가 아니다.
  • 보안: 커뮤니티의 반복되는 조언은 "모든 것에 자유 접근을 주지 말고 샌드박스 안에서 돌려라."
  • 메모리 한계: MEMORY.md 약 2,200자, USER.md 약 1,375자로 의도적으로 작다. 토큰 효율을 위한 설계지만 "결국 MEMORY.md 파일 아니냐"는 냉소도 있다.
  • 고객지원 같은 대외 업무에는 부적합: 헬프데스크 연동, 신뢰도 기반 라우팅, 에스컬레이션 같은 장치가 없다.
표절 논란 — 2026년 4월 중국 팀 EvoMap이 자사 오픈소스 Evolver(2월 1일 공개)의 10단계 자기진화 루프·3계층 메모리 구조를 Hermes의 self-evolution 모듈(3월 9일 생성)이 무단 차용했다고 GitHub 이슈(#17688)와 비교 보고서로 주장했다. Nous는 "저장소는 2025년 7월에 만들어졌고 우리가 선구자"라며 부인했고, 창립자 Teknium은 비교를 "brainless"라 일축했다. 이후 이슈 편집·게시물 삭제로 HN에서 대응 방식을 두고 논쟁이 있었다. 법적 결론은 없고 미해결 상태다. 기술 채택 판단과는 별개지만, 알고는 있어야 할 사안이다.

유사 오픈소스 에이전트 비교

가장 직접적인 경쟁자는 OpenClaw다. 둘 다 "메신저로 접근하는 셀프호스팅 개인 에이전트"이며 Hermes는 hermes claw migrate로 OpenClaw 스킬·메모리 이전 명령까지 제공한다. 2026년 6월 기준 일일 토큰 처리량은 Hermes 2,240억 vs OpenClaw 1,860억으로 역전됐다.

툴 레지스트리tools/*.py에 최상위 registry.register() 호출만 있으면 자동 발견. 수동 import 목록이 없다. 레지스트리가 스키마 수집·디스패치·가용성 체크·에러 래핑을 담당. 툴셋 단위로 플랫폼별 프리셋 게이팅
게이트웨이장기 실행 프로세스. 어댑터별 이벤트 정규화 → 세션 라우팅 → 인가(allowlist/DM 페어링) → 슬래시 명령 → 훅 라이프사이클 → cron 틱 → 세션 간 메시지 미러링
세션 저장SQLite + FTS5. 압축을 거친 세션의 부모/자식 계보 추적, 플랫폼별 격리, 경합 대응 원자적 쓰기
메모리·컨텍스트 엔진둘 다 추상 클래스 기반 single-select 플러그인. 한 번에 하나만 활성. Honcho 같은 외부 사용자 모델링도 이 인터페이스로 붙음
보안tools/approval.py 위험 명령 탐지, env_passthrough.py/credential_files.py로 자격증명 전달, 백엔드 샌드박싱. 코드 규약에 shlex.quote()와 os.path.realpath() 강제

개발자가 손댈 수 있는 여지

1. 플러그인 — 코어를 건드리지 않는 정식 확장 경로

플러그인은 ~/.hermes/plugins/(사용자), .hermes/plugins/(프로젝트), pip entry point 세 곳에서 발견된다. register(ctx) 하나로 툴·훅·슬래시 명령·CLI 서브커맨드·플랫폼 어댑터·메모리 프로바이더까지 등록한다.

~/.hermes/plugins/myplugin/__init__.py
import json

SCHEMA = {
    "name": "device_send_file",
    "description": "Send a file from this PC to a paired mobile device over the local network.",
    "parameters": {
        "type": "object",
        "properties": {
            "device_id": {"type": "string", "description": "Paired device identifier"},
            "path": {"type": "string", "description": "Absolute file path on the PC"},
        },
        "required": ["device_id", "path"],
    },
}

def send_file(args: dict, **kwargs) -> str:
    # 예외를 던지지 말고 항상 JSON 문자열을 반환한다 (플러그인 계약)
    try:
        result = my_grpc_client.send(args["device_id"], args["path"])   # 미검증 의사코드
        return json.dumps({"ok": True, "bytes": result.bytes_sent})
    except Exception as e:
        return json.dumps({"error": str(e)})

def audit(tool_name, args, result, task_id, duration_ms, **kwargs):
    if tool_name.startswith("device_"):
        print(f"[audit] {tool_name} {duration_ms}ms")

def register(ctx):
    ctx.register_tool(name="device_send_file", schema=SCHEMA,
                      handler=send_file, toolset="device")
    ctx.register_hook("post_tool_call", audit)
    ctx.register_command("devices", handler=lambda raw: "paired: ...",
                         description="List paired devices")
plugin.yaml
name: myplugin
version: 1.0.0
description: PC-to-mobile device bridge tools
provides_tools: [device_send_file]
provides_hooks: [post_tool_call]
# v2 선택 필드: manifest_version, api_version, requires_plugins,
#               python_dependencies, config_schema, capabilities

훅 이벤트는 15종이다. pre_tool_call(차단/승인 가능), post_tool_call, pre_llm_call(컨텍스트 주입 가능), post_llm_call, 세션 start/end/finalize/reset, pre/post_api_request, api_request_error, gateway_platform_event, kanban task claimed/completed/blocked. 미들웨어는 tool_request·llm_request(요청 재작성)와 tool_execution·llm_execution(next_call() 래핑) 4종이다. 호환성 계약이 명시돼 있다는 점이 좋다. 문서화된 메서드는 제거·개명하지 않고, 새 파라미터는 keyword-only 기본값, 폐기는 2개 마이너 릴리즈 이상 예고.

2. 메모리 프로바이더 / 컨텍스트 엔진 교체

인터페이스
class MemoryProvider(ABC):
    name: str
    def is_available(self) -> bool: ...
    def initialize(self, session_id: str, **kwargs) -> None: ...
    def sync_turn(self, user_content, assistant_content, **kwargs) -> None: ...
    def prefetch(self, query, **kwargs) -> str: ...       # 턴 시작 전 컨텍스트 주입
    def get_tool_schemas(self) -> list[dict]: ...         # 메모리 전용 툴 노출

class ContextEngine(ABC):
    name: str
    def update_from_response(self, usage) -> None: ...
    def should_compress(self, prompt_tokens=None) -> bool: ...
    def compress(self, messages, current_tokens=None, focus_topic=None,
                 force=False, memory_context="") -> list: ...

메모리 한계(2,200자)가 불만이면 이 인터페이스로 벡터 DB나 그래프 메모리를 직접 붙일 수 있다. 컨텍스트 엔진을 갈아끼우면 압축 전략(요약 vs 검색 기반 재구성)을 실험할 수 있다. 둘 다 single-select라 A/B 비교는 프로필을 나눠서 한다.

3. 플랫폼 어댑터 추가

ctx.register_platform(name, label, adapter_factory)로 게이트웨이에 새 채널을 붙인다. 카카오톡, LINE, 사내 메신저, 또는 자기 앱의 gRPC 채널이 여기에 들어갈 수 있다. 어댑터는 플랫폼 이벤트를 정규화해 넘기기만 하면 인가·세션·cron·훅은 게이트웨이가 처리한다.

4. 커스텀 프로바이더·로컬 모델

custom_providers에 OpenAI 호환 base_url만 적으면 된다. 로컬 모델 사용 시 함정은 컨텍스트 길이다. Ollama는 기본 4,096이라 OLLAMA_CONTEXT_LENGTH=32768이 필수이고, vLLM은 --enable-auto-tool-choice --tool-call-parser hermes를 붙여야 툴 호출이 동작한다. auxiliary 섹션으로 비전·압축·승인 판단 같은 보조 작업만 싸고 빠른 모델에 분리 배정할 수 있다.

5. 스킬 작성과 배포

SKILL.md는 목적·트리거·단계·예시 구조의 마크다운이다. agentskills.io 표준이라 Claude Code 등 다른 에이전트 스킬과 상호 호환된다. hub_taps에 자기 GitHub 저장소를 등록하면 팀 스킬 저장소가 된다. v0.21부터 생성 시 린터가 돈다.

6. 연구·평가 파이프라인

evals/와 trajectory export, Atropos 연동은 "에이전트가 남긴 궤적으로 모델을 파인튜닝"하는 루프를 열어 둔다. 자체 도메인 데이터로 소형 모델을 특화하려는 팀에게 드문 진입점이다.

PC-모바일 연동 앱과의 접점 아이디어

PC와 모바일을 WiFi/BLE/gRPC로 묶는 앱을 만드는 입장에서 Hermes를 보면, 에이전트 자체보다 "에이전트가 기기를 다루게 하는 층"이 비어 있다는 점이 눈에 띈다. Hermes는 PC 쪽 터미널·브라우저·파일은 잘 다루지만 옆에 있는 폰은 모른다.

안 맞는 사람설치·운영 없이 바로 쓰고 싶은 사람(Claude Code·OpenClaw SaaS), 고객 대면 자동화(전용 헬프데스크 AI)
