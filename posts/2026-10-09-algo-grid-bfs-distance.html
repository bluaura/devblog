distance 배열과 큐
0은 통로, 1은 벽인 격자에서 임의의 시작점부터 도착점까지 최소 이동 횟수를 구하는 문제다. 이 풀이의 중심은 distance 배열 하나다. -1이면 미방문, 0 이상이면 방문과 동시에 시작점으로부터의 거리를 뜻한다. 시작점을 0으로 두기 때문에 답은 "지나간 칸 수"가 아니라 "이동 횟수"가 된다. 학습 교재 05단원 예제 코드를 추적한 기록이며, 같은 배열로 경로까지 복원하는 변형을 덧붙였다 (Python 3 실행 확인).
BFS를 왜 쓰는지, 큐가 왜 최단 거리를 보장하는지는 BFS로 격자 최단 경로 구하기 — 코드 해설과 함정 4가지에서 다뤘다. 이 글은 그 글의 "개선한 코드"에 해당하는 형태를 처음부터 다시 추적하고, 시작·도착점이 인자로 들어올 때 생기는 경계 조건에 집중한다.

문제

0은 통로, 1은 벽인 격자가 주어진다. 상하좌우로 한 칸씩 움직여 start에서 end까지 가는 최소 이동 횟수를 구한다.

  • 입력: grid — 비어 있지 않은 0/1 직사각형 행렬. start, end — 범위 안의 (행, 열) 튜플.
  • 출력: 최소 이동 횟수. 지나간 칸의 개수가 아니다.
  • 같은 통로 칸에서 시작하고 끝나면 0.
  • 시작이나 끝이 벽이거나 도달할 수 없으면 -1.
격자start → end출력이유
[[0,0,1],[1,0,1],[0,0,0]](0,0) → (2,2)4오른쪽 1, 아래 2, 오른쪽 1
[[0,1,0]](0,0) → (0,2)-1가운데 벽에 막혀 도달 불가
[[0]](0,0) → (0,0)0이미 도착해 있다
[[1]](0,0) → (0,0)-1시작점이 벽이다

전체 코드

shortest_path.py
from collections import deque


def shortest_path(grid, start, end):
    rows, columns = len(grid), len(grid[0])
    sr, sc = start
    er, ec = end
    if grid[sr][sc] == 1 or grid[er][ec] == 1:
        return -1
    distance = [[-1] * columns for _ in range(rows)]
    distance[sr][sc] = 0
    queue = deque([start])
    while queue:
        r, c = queue.popleft()
        if (r, c) == end:
            return distance[r][c]
        for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
            nr, nc = r + dr, c + dc
            if not (0 <= nr < rows and 0 <= nc < columns):
                continue
            if grid[nr][nc] == 1 or distance[nr][nc] != -1:
                continue
            distance[nr][nc] = distance[r][c] + 1
            queue.append((nr, nc))
    return -1


def run_checks():
    assert shortest_path([[0, 0, 1], [1, 0, 1], [0, 0, 0]], (0, 0), (2, 2)) == 4
    assert shortest_path([[0, 1, 0]], (0, 0), (0, 2)) == -1
    assert shortest_path([[0]], (0, 0), (0, 0)) == 0
    assert shortest_path([[1]], (0, 0), (0, 0)) == -1
    print("05단원: 확인용 테스트 4개 통과")


if __name__ == "__main__":
    run_checks()

distance 배열의 세 가지 역할

이 코드에는 visited 배열도, 큐에 함께 넣는 거리 값도 없다. distance 하나가 전부 맡는다.

역할코드에서 쓰이는 곳의미
방문 표시distance[nr][nc] != -1-1이 아니면 이미 큐에 들어간 칸이다
거리 기록distance[r][c] + 1이웃의 거리는 현재 칸보다 1 크다
답return distance[r][c]도착점을 꺼낸 순간의 값이 최소 이동 횟수다

격자에 직접 거리를 덮어쓰는 방식과 비교하면 차이가 분명하다.

항목격자에 직접 기록distance 배열 분리
입력 격자호출 후 값이 바뀐다그대로 보존된다
거리 값벽(1)과 겹치지 않게 2부터 시작, 마지막에 −20부터 시작, 보정 없음
미방문 판정값이 0인가값이 -1인가
추가 메모리없음O(R·C)

코드 한 줄씩 보기

탐색 전에 벽부터 거른다

if grid[sr][sc] == 1 or grid[er][ec] == 1:
    return -1

BFS 본문은 "이웃이 벽인가"만 검사하고 시작 칸 자체는 검사하지 않는다. 그래서 이 줄이 없으면 벽 위에서 탐색이 시작된다. 도착점이 벽인 경우는 어차피 도달하지 못해 -1이 나오지만, 격자 전체를 다 돌고 나서야 알게 되므로 미리 끊는 편이 낫다.

시작점의 거리는 0

distance = [[-1] * columns for _ in range(rows)]
distance[sr][sc] = 0
queue = deque([start])

시작점은 아직 한 번도 움직이지 않았으므로 0이다. 여기를 1로 두면 답이 "지나간 칸의 개수"로 바뀐다. 방문 표시와 큐 삽입을 같은 시점에 하는 것도 본문과 동일한 규칙이다.

도착 판정은 꺼낼 때 한다

r, c = queue.popleft()
if (r, c) == end:
    return distance[r][c]

이웃을 발견했을 때가 아니라 큐에서 꺼냈을 때 판정한다. 시작점도 큐에서 꺼내지므로 start == end인 경우가 별도 분기 없이 0으로 처리된다.

이웃 검사는 범위 → 벽 → 방문 순서

if not (0 <= nr < rows and 0 <= nc < columns):
    continue
if grid[nr][nc] == 1 or distance[nr][nc] != -1:
    continue
distance[nr][nc] = distance[r][c] + 1
queue.append((nr, nc))

범위 검사가 반드시 먼저다. 두 조건을 통과한 칸에만 거리를 쓰고 큐에 넣는다. 거리를 쓰는 순간이 곧 방문 표시이므로 같은 칸이 큐에 두 번 들어가지 않는다.

예제 추적

[[0, 0, 1], [1, 0, 1], [0, 0, 0]]에서 (0,0) → (2,2)를 따라간다. 방향 순서는 상, 하, 좌, 우다.

놓치기 쉬운 함정

실수입력잘못된 결과기대값
시작·도착 벽 검사 생략[[1]], (0,0) → (0,0)0-1
end를 리스트로 전달예제 격자, (0,0) → [2, 2]-14
시작점 거리를 1로 설정예제 격자54

1. 시작점이 벽인데 0을 반환한다

벽 검사를 빼고 [[1]]을 넣으면, 시작점을 큐에서 꺼내자마자 도착 판정에 걸려 0이 나온다. 실행해서 확인한 결과다. "도착 판정을 꺼낼 때 한다"는 장점이 벽 검사 없이는 오히려 오답을 만든다.

2. 튜플과 리스트는 같지 않다

(2, 2) == [2, 2]는 False다. end가 리스트로 들어오면 도착 판정이 한 번도 참이 되지 않아 에러 없이 -1이 나온다. 입력을 직접 파싱하는 환경이라면 end = tuple(end)로 맞추거나 r == er and c == ec로 비교한다.

3. 이동 횟수와 칸 수를 혼동한다

칸 수는 항상 이동 횟수보다 1 크다. 문제마다 요구가 다르므로 시작점 초기값(0 또는 1)을 문제 문장에 맞춰 정한다.

4. 범위 검사를 벽 검사 뒤에 둔다

파이썬은 음수 인덱스를 허용한다. nr이 -1이면 grid[-1]은 에러가 아니라 마지막 행을 읽는다. 범위 검사가 뒤에 있으면 예외 없이 반대편 칸을 조회하게 되어 원인을 찾기 어렵다.

5. 2차원 배열을 곱셈으로 만든다

bad = [[-1] * 3] * 2
bad[0][0] = 0
print(bad)  # [[0, -1, -1], [0, -1, -1]]

바깥 곱셈은 같은 행 객체를 여러 번 참조한다. 한 칸을 바꾸면 모든 행이 함께 바뀐다. [[-1] * columns for _ in range(rows)]처럼 행마다 새로 만든다.

경로까지 복원하기

교재 범위를 넘어 직접 추가한 변형이다. 이동 횟수뿐 아니라 실제 경로가 필요할 때, 부모 칸을 따로 저장하지 않고 distance만으로 되짚을 수 있다. 도착점에서 출발해 거리가 정확히 1 작은 이웃으로 계속 옮겨 가면 시작점에 닿는다.

shortest_route.py
from collections import deque


def shortest_route(grid, start, end):
    rows, columns = len(grid), len(grid[0])
    start, end = tuple(start), tuple(end)
    sr, sc = start
    er, ec = end
    if grid[sr][sc] == 1 or grid[er][ec] == 1:
        return []
    distance = [[-1] * columns for _ in range(rows)]
    distance[sr][sc] = 0
    queue = deque([start])
    while queue:
        r, c = queue.popleft()
        if (r, c) == end:
            break
        for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
            nr, nc = r + dr, c + dc
            if not (0 <= nr < rows and 0 <= nc < columns):
                continue
            if grid[nr][nc] == 1 or distance[nr][nc] != -1:
                continue
            distance[nr][nc] = distance[r][c] + 1
            queue.append((nr, nc))
    if distance[er][ec] == -1:
        return []

    # 도착점에서 거리가 1씩 줄어드는 이웃을 따라 거꾸로 올라간다
    path = [end]
    r, c = end
    while (r, c) != start:
        for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
            pr, pc = r + dr, c + dc
            if (0 <= pr < rows and 0 <= pc < columns
                    and distance[pr][pc] == distance[r][c] - 1):
                r, c = pr, pc
                break
        path.append((r, c))
    path.reverse()
    return path


print(shortest_route([[0, 0, 1], [1, 0, 1], [0, 0, 0]], (0, 0), (2, 2)))
# [(0, 0), (0, 1), (1, 1), (2, 1), (2, 2)]

도착점을 꺼낸 시점에 조기 종료해도 복원에는 문제가 없다. BFS는 거리 순서로 칸을 꺼내므로, 도착점보다 거리가 작은 칸은 그때 이미 모두 기록되어 있다. 도달할 수 없으면 빈 리스트를 반환하고, 최단 경로가 여러 개면 방향 순서에 따라 그중 하나가 나온다.
