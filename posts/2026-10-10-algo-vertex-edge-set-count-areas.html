로봇이 동서남북으로 한 칸씩 움직이며 선을 그릴 때, 그 선으로 완전히 둘러싸인 영역의 개수를 구하는 문제다. 도형을 그려 놓고 안쪽을 세는 것이 아니라, 이동할 때마다 한 가지만 확인한다. 처음 그리는 선분이 이미 지나간 점에 닿는가. 그렇다면 고리가 하나 닫힌 것이고 영역이 하나 늘어난다. 이를 위해 "지나간 점"과 "그린 선분"을 서로 다른 집합으로 기억한다. 학습 교재 12단원 예제 코드를 추적한 기록이며, 같은 답을 뺄셈 한 번으로 내는 오일러 공식 버전을 덧붙였다 (Python 3 실행 확인).

문제

로봇이 격자점 위를 동서남북으로 한 칸씩 움직이며 지나간 자리에 선을 그린다. 그린 선으로 완전히 둘러싸인 영역이 몇 개인지 구한다.

  • 입력: info — 방향 문자열. 0 = 동, 1 = 서, 2 = 남, 3 = 북. 시작점은 (0, 0)으로 둔다.
  • 같은 선을 다시 지나가도 새 영역은 생기지 않는다.
  • 경로 전체가 시작점으로 돌아오지 않아도, 중간에 만들어진 영역은 센다.
  • 출력: 닫힌 영역의 개수. 넓이나 방문한 칸 수가 아니다.
info출력설명
"01"0동쪽으로 갔다가 같은 선으로 되돌아옴
"0312"1동 → 북 → 서 → 남으로 정사각형 하나
"03123021"1정사각형을 그린 뒤 같은 변을 반대 방향으로 다시 돎
"33302111220000"2작은 사각형 하나와 큰 사각형 하나

전체 코드

count_areas.py
def count_areas(info):
    directions = ((1, 0), (-1, 0), (0, -1), (0, 1))
    current = (0, 0)
    vertices = {current}
    edges = set()
    areas = 0
    for direction in info:
        dx, dy = directions[int(direction)]
        neighbor = (current[0] + dx, current[1] + dy)
        edge = tuple(sorted((current, neighbor)))
        if edge not in edges:
            if neighbor in vertices:
                areas += 1
            edges.add(edge)
        vertices.add(neighbor)
        current = neighbor
    return areas


def run_checks():
    assert count_areas("01") == 0
    assert count_areas("0312") == 1
    assert count_areas("03123021") == 1
    assert count_areas("33302111220000") == 2
    print("12단원: 확인용 테스트 4개 통과")


if __name__ == "__main__":
    run_checks()

왜 정확히 하나씩 늘어나는가

로봇은 한 붓으로 그리므로 지금까지 그린 선은 전부 이어져 있다. 현재 위치와 도착점이 이미 선으로 연결되어 있는 상태에서 둘을 잇는 새 선분을 하나 그으면, 기존 경로와 새 선분이 고리를 하나 만든다. 새 선분 하나는 어떤 영역(또는 바깥) 하나를 둘로 가를 뿐이라, 늘어나는 영역은 항상 하나다.

점과 선분을 따로 기억해야 하는 이유

점만 기억하면 "되돌아온 것"과 "고리를 닫은 것"을 구분할 수 없다. "01"은 시작점으로 돌아오지만 같은 선을 밟았을 뿐이다. 선분만 기억하면 "새 선분이 기존 도형에 닿았는지"를 알 수 없다. 두 정보가 모두 필요하다.

판별 기준 — 격자 문제에서 "칸"이 아니라 "선"이나 "변"이 주인공이면 좌표 하나로는 상태를 표현할 수 없다. 선분을 (점, 점) 쌍으로 만들어 집합에 넣는다. 방향이 의미 없는 선분이라면 두 점을 정렬해 한 가지 표기로 통일한다.

코드 한 줄씩 보기

방향 표

directions = ((1, 0), (-1, 0), (0, -1), (0, 1))
dx, dy = directions[int(direction)]

문자 '0' ~ '3'을 정수로 바꿔 인덱스로 쓴다. 순서는 문제의 정의(0 = 동, 1 = 서, 2 = 남, 3 = 북)와 같아야 한다. 여기서는 (x, y) 좌표계이고 북쪽이 y + 1이다. 행·열 격자와 달리 위쪽이 양수다. 다만 이 문제는 모양만 중요해서 위아래가 뒤집혀도 답은 같다.

선분을 한 가지 표기로

edge = tuple(sorted((current, neighbor)))

(0, 0)에서 (1, 0)으로 간 선과 (1, 0)에서 (0, 0)으로 간 선은 같은 선이다. 두 끝점을 정렬하면 어느 방향으로 지나가든 같은 튜플이 된다. 집합의 원소는 변경 불가능해야 하므로 sorted가 돌려준 리스트를 tuple로 감싼다.

판정

if edge not in edges:
    if neighbor in vertices:
        areas += 1
    edges.add(edge)
vertices.add(neighbor)
current = neighbor

바깥 조건이 "새 선분인가", 안쪽 조건이 "도착점을 이미 지났는가"다. 둘 다 참일 때만 영역이 늘어난다. vertices.add(neighbor)는 판정 뒤에 온다. 먼저 넣으면 도착점이 항상 "이미 방문"으로 보인다.

시작점을 처음부터 vertices에 넣어 두는 것도 중요하다. 로봇은 움직이기 전에 이미 시작점 위에 있다.

네 줄 모두 잘못 짠 코드를 실행해 얻은 값이다.

1. 되돌아온 것과 닫은 것을 구분하지 않는다

방문한 점에 다시 왔다는 사실만으로는 영역이 생겼다고 할 수 없다. 왔던 길을 되짚어도 방문한 점에 닿기 때문이다. "새 선분으로" 닿았을 때만 센다.

2. 방향이 다른 같은 선분을 다른 것으로 본다

(a, b)와 (b, a)를 구분해 저장하면, 정사각형을 반대로 한 바퀴 돌 때 네 변이 모두 새 선분으로 처리되어 4가 더해진다. "01"도 같은 이유로 1이 된다. 선에는 방향이 없으므로 정렬해서 저장한다.

3. 시작점을 빠뜨린다

vertices를 빈 집합으로 시작하면 첫 고리를 닫으며 시작점으로 돌아올 때 "처음 보는 점"으로 처리된다. 네 번째 예제에서는 A는 잡히지만 시작점에서 닫히는 B를 놓쳐 1이 나온다.

4. 넓이나 칸 수를 센다

2 × 2 정사각형 한 바퀴("00331122")의 답은 4가 아니라 1이다. 그 안에 십자 모양으로 선을 더 그어야("003311220332100") 4가 된다. 영역의 개수는 "고리가 닫힌 횟수"이지 크기와 무관하다.

5. 리스트를 집합에 넣으려 한다

sorted는 리스트를 돌려주고, 리스트는 집합에 넣을 수 없다(TypeError: unhashable type). 좌표도 선분도 튜플로 만든다.

6. 그림을 실제로 그려서 세려고 한다

2차원 배열에 선을 찍고 안쪽을 채워 세는 방법도 가능은 하다. 하지만 좌표가 음수로 나가고, 선이 칸의 경계에 있어 배열을 두 배로 확대해야 하며, 이동 범위만큼 메모리를 쓴다. 집합 두 개로 세면 이동 횟수에 비례하는 시간과 공간으로 끝난다.

변형: 오일러 공식으로 한 번에

교재 범위를 넘어 직접 추가한 변형이다. 원본의 판정을 다시 보면, 새 선분을 그릴 때 점이 함께 늘면 영역은 그대로고, 선분만 늘면 영역이 하나 늘어난다. 즉 영역 수는 처음부터 끝까지 선분 수 − 점 수 + 1과 같다. 이어진 평면 도형에서 성립하는 오일러 공식의 한 형태다.

count_areas_euler.py
def count_areas_euler(info):
    directions = ((1, 0), (-1, 0), (0, -1), (0, 1))
    current = (0, 0)
    vertices = {current}
    edges = set()
    for direction in info:
        dx, dy = directions[int(direction)]
        neighbor = (current[0] + dx, current[1] + dy)
        edges.add(tuple(sorted((current, neighbor))))
        vertices.add(neighbor)
        current = neighbor
    return len(edges) - len(vertices) + 1

조건문이 사라지고 집합이 중복을 알아서 걸러 준다. 다만 이 공식은 그림이 한 덩어리로 이어져 있을 때만 맞는다. 로봇 한 대가 끊지 않고 그리는 이 문제에서는 항상 성립하지만, 펜을 들었다 놓거나 로봇이 여러 대인 변형에서는 덩어리 수를 따로 세어 보정해야 한다.

검증에는 세 번째 방식을 따로 구현했다. 함정 6에서 말한 "실제로 그려서 세기"로, 좌표를 두 배로 확대한 격자에 점과 선분 중점을 벽으로 찍고, 바깥에서부터 빈칸을 채운 뒤 남은 빈 구역의 개수를 센다.
