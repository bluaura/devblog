행렬을 읽는 비용뿐
N×N 행렬에 수를 더하기만 해서 모든 행의 합과 모든 열의 합을 같은 값으로 만들 때, 더하는 양의 최소 합을 구하는 문제다. 값을 줄일 수 없으므로 목표 합 T는 행 합·열 합 중 가장 큰 값보다 작을 수 없다. 이것이 답의 하한이고, 실제로 그 값에 딱 맞춰 채울 수 있다. 그래서 행렬을 실제로 고치지 않고 N × T − 전체 합 한 줄로 답이 나온다. 학습 교재 04단원 예제 코드를 추적한 기록이며, 하한이 달성 가능하다는 것을 보여 주는 구성 코드를 덧붙였다 (Python 3 실행 확인).

문제

N×N 행렬이 주어진다. 원하는 칸에 수를 더해서 모든 행의 합과 모든 열의 합을 같은 값으로 만든다.

  • 입력: matrix — 비어 있지 않은 N×N 행렬. 원소는 음이 아닌 정수다.
  • 기존 값을 줄일 수는 없다. 더하기만 가능하다.
  • 출력: 추가한 수의 전체 합의 최솟값. 목표 합이나 바뀐 행렬이 아니다.
입력출력이유
[[1, 2], [3, 4]]4가장 큰 합은 2행의 7. 전체를 7로 맞추려면 2×7 − 10 = 4
[[0, 0], [0, 0]]0이미 모든 합이 0으로 같다
[[5, 0], [5, 0]]10행 합은 5로 같지만 1열의 합이 10이다
[[3]]01×1은 행 합과 열 합이 항상 같다

전체 코드

balance_extra.py
def balance_extra(matrix):
    size = len(matrix)
    row_sums = [sum(row) for row in matrix]
    column_sums = [sum(matrix[r][c] for r in range(size))
                   for c in range(size)]
    target = max(max(row_sums), max(column_sums))
    return size * target - sum(row_sums)


def run_checks():
    assert balance_extra([[1, 2], [3, 4]]) == 4
    assert balance_extra([[0, 0], [0, 0]]) == 0
    assert balance_extra([[5, 0], [5, 0]]) == 10
    assert balance_extra([[3]]) == 0
    print("04단원: 확인용 테스트 4개 통과")


if __name__ == "__main__":
    run_checks()

핵심 아이디어

어느 칸에 얼마를 더할지 정하려 들면 경우의 수가 끝이 없다. 이 문제는 "어떻게 채울까"가 아니라 "최종 목표 합 T가 얼마여야 하는가"만 정하면 풀린다.

  1. T가 정해지면 답도 정해진다 — 완성된 행렬은 N개 행의 합이 모두 T이므로 전체 합이 N×T다. 원래 전체 합을 S라 하면 추가량은 어떻게 채우든 N×T − S다.
  2. T에는 하한이 있다 — 값을 줄일 수 없으니 어떤 행·열의 합도 지금보다 작아질 수 없다. 따라서 T는 현재 행 합·열 합 중 최댓값 이상이어야 한다.
  3. T가 작을수록 추가량이 적다 — N×T − S는 T에 대해 증가하므로, 가능한 가장 작은 T인 "최댓값 그 자체"가 최적이다.
판별 기준 — "최소 비용으로 조건을 맞춰라"에서 직접 구성이 복잡해 보이면, 먼저 "답이 이보다 작을 수 없다"는 하한을 찾는다. 그 하한에 딱 맞는 방법이 존재한다는 것까지 보이면 하한이 곧 정답이고, 구성 과정을 코드로 옮길 필요가 없다.

코드 한 줄씩 보기

행 합과 열 합을 따로 집계한다

row_sums = [sum(row) for row in matrix]
column_sums = [sum(matrix[r][c] for r in range(size))
               for c in range(size)]

행은 리스트 하나라 sum(row)로 끝나고, 열은 행 번호 r을 돌리며 같은 열 c의 값을 모아야 한다. 열 합은 [sum(column) for column in zip(*matrix)]로 써도 결과가 같다. zip(*matrix)가 행렬을 열 단위로 묶어 준다.

목표 합은 양쪽의 최댓값

target = max(max(row_sums), max(column_sums))

행만 보거나 열만 보면 안 된다. 행 합이 전부 같아도 열 합이 더 클 수 있기 때문이다 (아래 예제 추적의 두 번째 경우).

행렬을 고치지 않고 답만 계산한다

return size * target - sum(row_sums)

sum(row_sums)는 행렬 전체 합 S다. 이미 구해 둔 행 합을 다시 더하는 것이라 행렬을 한 번 더 순회하지 않는다. sum(column_sums)를 써도 같은 값이다.

하한은 정말 달성되는가

"T는 최댓값 이상이어야 한다"는 것만으로는 부족하다. T를 최댓값으로 두고도 항상 채울 수 있다는 것까지 보여야 공식이 정답이 된다.

근거는 부족분의 합이 같다는 점이다. 행 i의 부족분을 T − 행 합, 열 j의 부족분을 T − 열 합이라 하면, 둘 다 전부 더했을 때 N×T − S로 같다. 즉 부족한 행이 하나라도 있으면 부족한 열도 반드시 있다. 그 교차 칸에 둘 중 작은 부족분만큼 더하면 다른 행·열을 건드리지 않고 적어도 하나가 T에 도달한다. 이를 반복하면 전부 채워진다.

교재 범위를 넘어 직접 추가한 구성 코드다. 행 포인터와 열 포인터를 하나씩 전진시키는 방식이다.

balance_fill.py
def balance_fill(matrix):
    size = len(matrix)
    result = [row[:] for row in matrix]
    row_sums = [sum(row) for row in result]
    column_sums = [sum(column) for column in zip(*result)]
    target = max(max(row_sums), max(column_sums))

    r = c = 0
    while r < size and c < size:
        add = min(target - row_sums[r], target - column_sums[c])
        result[r][c] += add
        row_sums[r] += add
        column_sums[c] += add
        if row_sums[r] == target:
            r += 1
        if column_sums[c] == target:
            c += 1
    return result


print(balance_fill([[1, 2], [3, 4]]))  # [[4, 3], [3, 4]]
print(balance_fill([[5, 0], [5, 0]]))  # [[5, 5], [5, 5]]

한 번 돌 때마다 행이나 열 중 하나는 반드시 T에 도달하므로 반복은 최대 2N − 1번이다. 한쪽 포인터가 끝에 닿으면 그쪽은 모두 T이고, 전체 합이 N×T가 되었으니 반대쪽도 모두 T다.

놓치기 쉬운 함정

1. 행 합만 보고 목표를 정한다

[[5, 0], [5, 0]]은 행 합이 5, 5로 이미 같다. 행만 보면 답이 0처럼 보이지만 열 합은 10, 0이다. 1열의 10을 줄일 수 없으니 T는 10이어야 하고 답은 10이다.

2. 행 부족분과 열 부족분을 둘 다 더한다

[[1, 2], [3, 4]]에서 행 부족분은 4 + 0 = 4, 열 부족분은 3 + 1 = 4다. 이 둘을 더해 8이라고 답하면 틀린다. 한 칸에 더한 수는 그 칸이 속한 행과 열을 동시에 채운다. 추가량은 둘 중 한쪽만 세면 된다.

3. 출력 대상을 착각한다

구하는 값은 목표 합 T(7)도, 완성된 행렬도 아니고 추가한 양의 합(4)이다. 문제 설명에 따로 적혀 있을 만큼 자주 틀리는 지점이다.

4. 실제로 행렬을 채우려 든다

답만 구하는 문제에서는 구성이 필요 없다. 채우는 방법은 여러 가지지만 추가량은 T에만 의존하므로 모두 같은 값이 나온다. 구성 코드는 "가능하다"는 것을 확인하는 용도이지 답을 구하는 데 쓰지 않는다.

5. 평균으로 맞추려 한다

합을 같게 만든다는 말에서 평균을 떠올리기 쉽지만, 줄일 수 없다는 조건 때문에 기준은 평균이 아니라 최댓값이다.

  • 공식으로 답이 나오는 문제도, 구성 코드와 무작위 검증을 한 번 돌려 두면 공식을 믿을 근거가 생긴다.
