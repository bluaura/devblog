화합물 ID가 일렬로 놓여 있을 때 연속한 length개 구간과 목표 ID 하나를 골라, 목표와 차이가 1 이하인 화합물 수를 최대로 만드는 문제다. 목표는 0 ~ 15 중 16가지뿐이라 전부 시도한다. 목표를 하나 고정하면 남는 일은 "길이가 고정된 창을 한 칸씩 밀며 조건에 맞는 개수를 유지"하는 것이고, 창을 밀 때마다 새로 세지 않고 들어온 값과 나간 값만 반영한다. 학습 교재 07단원 예제 코드를 추적한 기록이며, 빈도 배열로 한 번만 훑는 변형을 덧붙였다 (Python 3 실행 확인).

문제

화합물 ID가 원래 순서대로 놓여 있다. 연속한 length개 구간과 목표 ID를 하나씩 선택한다. 구간 안에서 목표 ID와의 차이가 1 이하인 화합물이 반응한다. 반응 개수의 최댓값을 구한다.

  • 입력: ids — 0 ~ 15의 ID 리스트. length — 구간 길이, 1 이상 len(ids) 이하.
  • 목표는 0 ~ 15의 어느 값이든 가능하다. 구간 안에 없는 값이어도 된다.
  • 순서를 바꿀 수 없다. 정렬하면 안 된다.
  • 출력: 최대 반응 개수. 구간 위치나 목표 값이 아니다.
idslength출력이유
[7, 15, 3, 3, 7, 8, 7, 15, 3, 3]84앞 8개에서 목표 7: 7, 7, 8, 7
[0, 2, 0, 2]44목표 1: 0과 2가 모두 차이 1
[0, 15, 0, 15, 0]32어느 구간이든 같은 쪽 값은 최대 2개
[15, 15, 15]22목표 14 또는 15

전체 코드

maximum_product.py
def maximum_product(ids, length):
    best = 0
    for target in range(16):
        count = sum(abs(ids[i] - target) <= 1 for i in range(length))
        best = max(best, count)
        for right in range(length, len(ids)):
            if abs(ids[right] - target) <= 1:
                count += 1
            if abs(ids[right - length] - target) <= 1:
                count -= 1
            best = max(best, count)
    return best


def run_checks():
    assert maximum_product([7, 15, 3, 3, 7, 8, 7, 15, 3, 3], 8) == 4
    assert maximum_product([0, 2, 0, 2], 4) == 4
    assert maximum_product([0, 15, 0, 15, 0], 3) == 2
    assert maximum_product([15, 15, 15], 2) == 2
    print("07단원: 확인용 테스트 4개 통과")


if __name__ == "__main__":
    run_checks()

함수 이름의 product는 곱이 아니라 반응 생성물이라는 뜻이다. 곱셈은 어디에도 없다.

핵심 아이디어

고를 것이 두 가지(구간, 목표)라서 복잡해 보이지만, 하나를 고정하면 다른 하나는 단순한 문제가 된다.

  1. 목표를 전부 시도한다 — 값의 범위가 0 ~ 15로 좁다. 16가지를 모두 돌려도 비용이 작다.
  2. 목표가 정해지면 각 칸은 0 또는 1이다 — "목표와 차이가 1 이하인가"는 칸마다 참·거짓으로 결정된다. 문제는 "길이 length인 연속 구간 중 참이 가장 많은 구간"으로 바뀐다.
  3. 창을 밀 때 바뀌는 것은 두 칸뿐이다 — 오른쪽으로 한 칸 밀면 새 값 하나가 들어오고 가장 왼쪽 값 하나가 나간다. 가운데 length − 1개는 그대로이므로 다시 셀 필요가 없다.
창 이동 (length = 4)

 [ a  b  c  d ] e  f        count
   a [ b  c  d  e ] f       count + (e 조건) - (a 조건)
   a  b [ c  d  e  f ]      count + (f 조건) - (b 조건)
판별 기준 — "연속한 k개", "길이가 고정된 구간"에서 합·개수·최댓값을 구하라고 하면 슬라이딩 윈도우를 먼저 떠올린다. 구간마다 다시 계산하는 O(N × k)를 O(N)으로 줄이는 것이 목적이다. 정렬이 금지된 문제는 순서 자체가 조건이라는 신호다.

코드 한 줄씩 보기

목표 16가지를 바깥에서 돈다

for target in range(16):

set(ids)가 아니라 range(16)이다. 목표는 구간에 없는 값이어도 되기 때문이다. 이 차이가 두 번째 예제의 정답을 가른다.

첫 창은 직접 센다

count = sum(abs(ids[i] - target) <= 1 for i in range(length))
best = max(best, count)

파이썬에서 True는 1, False는 0으로 더해지므로 조건식을 그대로 sum에 넣으면 개수가 된다. 첫 창의 결과로 best를 바로 갱신하는 줄이 중요하다. length가 전체 길이와 같으면 아래 반복문이 한 번도 돌지 않기 때문이다.

한 칸 밀기

for right in range(length, len(ids)):
    if abs(ids[right] - target) <= 1:
        count += 1
    if abs(ids[right - length] - target) <= 1:
        count -= 1
    best = max(best, count)
인덱스의미
right새로 창에 들어오는 칸. 창의 오른쪽 끝
right - length창에서 빠지는 칸. 직전 창의 왼쪽 끝
right - length + 1새 창의 왼쪽 끝 (코드에는 쓰이지 않음)

abs(값 - target) <= 1은 목표가 0이나 15여도 그대로 동작한다. 배열 인덱스가 아니라 값의 차이를 보는 것이라 경계 처리가 따로 필요 없다.

놓치기 쉬운 함정

실수입력잘못된 결과기대값
목표를 구간 안의 값에서만 고름[0, 2, 0, 2], 424
정렬한 뒤 구간을 잡음[0, 15, 0, 15, 0], 332
첫 창에서 best를 갱신하지 않음[0, 2, 0, 2], 404
나가는 칸을 right - length + 1로 계산[0, 5, 0], 221

네 줄 모두 실제로 잘못 짠 코드를 실행해 얻은 값이다.

1. 목표는 구간에 없는 값일 수 있다

[0, 2, 0, 2]에서 목표를 0이나 2로 잡으면 2개만 반응한다. 그 사이의 1을 잡아야 4개가 전부 반응한다. "등장한 값만 후보"라는 직관이 틀리는 경우이므로 0 ~ 15를 전부 돈다.

2. 정렬하면 다른 문제가 된다

정렬하면 같은 값이 모여서 답이 커진다. [0, 15, 0, 15, 0]을 정렬하면 0이 세 개 붙어 3이 나오지만, 원래 순서에서는 연속 3개 안에 0이 최대 2개다. "연속 구간"은 원래 위치를 기준으로 한 조건이다.

3. 반복문이 한 번도 돌지 않는 경우

length == len(ids)이면 창이 하나뿐이라 미는 반복문은 실행되지 않는다. best 갱신이 반복문 안에만 있으면 0을 반환한다. 앞의 긴 예제에서는 이 실수가 드러나지 않는다(4가 그대로 나온다). 창이 여러 개라 뒤쪽 창에서 같은 최댓값을 다시 만나기 때문이다.

4. 나가는 칸의 인덱스

창 길이가 length이고 오른쪽 끝이 right이면 왼쪽 끝은 right - length + 1이다. 빠져야 하는 칸은 그보다 하나 앞인 right - length다. [0, 5, 0], 길이 2에서 목표 0을 보면, 두 번째 0이 들어올 때 첫 번째 0이 나가야 1이 유지된다. 인덱스를 하나 밀려 쓰면 5를 내보내게 되어 2가 된다.

5. 창마다 처음부터 다시 센다

결과는 맞지만 느리다. 창마다 length개를 다시 보면 O(16 × N × length)가 된다.

방식 (N = 5,000, length = 500)조건 검사 횟수실행 시간
창마다 다시 세기약 3,600만1.87초
슬라이딩 윈도우 (이 코드)약 15만0.009초

실행 시간은 한 번 측정한 값이라 비율만 참고한다. 구간 길이가 길수록 차이가 벌어진다.

변형: 빈도 배열로 한 번만 훑기

교재 범위를 넘어 직접 추가한 변형이다. 원본은 "목표를 고정하고 창을 민다"를 16번 반복한다. 순서를 뒤집어 창을 한 번만 밀면서 창 안의 값별 개수를 유지해도 된다. 목표 t의 반응 개수는 값이 t − 1, t, t + 1인 칸의 개수 합이다.

maximum_product_freq.py
def maximum_product_freq(ids, length):
    freq = [0] * 18          # 값 v는 freq[v + 1]에 저장, 양 끝은 경계용 0
    for value in ids[:length]:
        freq[value + 1] += 1
    best = max(freq[t] + freq[t + 1] + freq[t + 2] for t in range(16))
    for right in range(length, len(ids)):
        freq[ids[right] + 1] += 1
        freq[ids[right - length] + 1] -= 1
        best = max(best, max(freq[t] + freq[t + 1] + freq[t + 2] for t in range(16)))
    return best

빈도 배열은 값의 차이가 아니라 인덱스로 접근하므로 경계가 문제가 된다. 목표 0의 왼쪽(−1)과 목표 15의 오른쪽(16)을 읽게 되기 때문이다. 배열을 한 칸씩 밀어 크기 18로 잡고 양 끝을 0으로 두면 조건문 없이 처리된다. 밀지 않으면 freq[-1]이 파이썬에서 에러 없이 마지막 칸을 읽어 조용히 틀린다.

창 갱신ids[right]가 들어오고 ids[right - length]가 나간다
