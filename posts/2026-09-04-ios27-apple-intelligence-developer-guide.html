iOS 27 / macOS 27(Golden Gate)의 Apple Intelligence는 "Siri AI"라는 이름으로 완전히 새로 만들어졌고, 개발자에게 열린 문은 두 개다. 하나는 Foundation Models 프레임워크(온디바이스 3B 모델, 서버 PCC 모델, Claude·Gemini까지 같은 Swift API로 호출), 다른 하나는 App Intents의 App Schema(내 앱의 데이터와 액션을 Siri가 이해하고 실행하게 하는 계약)다. 결론부터 말하면 Apple은 화면을 읽고 클릭하는 "컴퓨터 유즈" 에이전트를 만들지 않았다. 개발자가 미리 선언한 액션만 실행하는 구조라서, Hermes Agent 같은 범용 기기 제어 에이전트는 iOS에서는 여전히 불가능하고 macOS에서만 서드파티가 접근성 API로 구현하는 형태로 남아 있다.

Siri AI 아키텍처 — Orchestrator, Semantic Index, App Toolbox

Apple이 공식적으로 설명한 Siri AI 구조는 세 요소로 이루어진다.

  1. System Orchestrator — 요청을 받아 온디바이스에서 처리할지 Private Cloud Compute(PCC)로 보낼지 결정하는 라우터. Federighi는 "간단한 요청은 전부 로컬에서, 더 복잡한 질문은 더 큰 지능을 끌어온다"고 설명했다.
  2. Spotlight Semantic Index — 메시지, 메일, 사진, 노트, 캘린더, 파일 등 개인 콘텐츠의 시맨틱 인덱스. 서드파티 앱은 IndexedEntity로 자기 데이터를 여기에 넣을 수 있다. 전부 온디바이스.
  3. App Toolbox — 앱들이 App Intents/App Schema로 선언한 액션 모음. Siri는 이 도구 상자 안의 액션만 실행한다.

사용자 관점에서 Siri AI가 제공하는 능력은 네 가지다. 개인 컨텍스트 검색, 화면 인식(onscreen awareness), 웹 기반 세계 지식, 그리고 앱 간 액션 실행. 여기에 대화 기록이 iCloud로 동기화되는 별도 Siri 앱, 내 문체를 흉내내는 Write with Siri, 카메라에 통합된 Visual Intelligence "Siri mode"가 붙는다. macOS에서는 Spotlight(Cmd+Space)가 "Search or Ask"로 바뀌어 Siri 진입점이 된다.

모델 — Google과의 관계 정리

가장 오해가 많은 부분이다. Apple은 1월에 "Google의 기술이 Apple Foundation Models의 가장 유능한 기반"이라고 발표했지만, WWDC에서 Federighi가 직접 정정한 내용은 다음과 같다.

  • Siri AI는 Apple 자체 모델(AFM 3)로 동작한다. Gemini 모델, Google Assistant 코드, Google 검색 인프라는 전혀 쓰지 않는다.
  • Google의 기여는 두 가지다. Gemini 프론티어 모델 출력으로부터의 증류(distillation), 그리고 최상위 모델 AFM 3 Cloud Pro를 Google Cloud의 NVIDIA GPU 위에서 호스팅하는 것. 이 서버도 PCC 인증 환경으로 운영된다.
  • 3세대 AFM은 5개 모델로 구성된다. AFM 3 Core(3B, 온디바이스), AFM 3 Core Advanced(20B sparse MoE, 쿼리당 1~4B 활성화, 12GB RAM 기기 전용), AFM 3 Cloud(PCC), ADM 3 Cloud(이미지), AFM 3 Cloud Pro(에이전트형 툴 사용).

코드로 보는 변화 — 모델 교체와 이미지 입력

아래는 WWDC26 세션(241, 242, 339)의 API 형태를 기준으로 정리한 의사코드다. 베타 기간 중 시그니처가 여러 번 바뀌었으므로 실제 사용 시 최신 문서로 확인해야 한다.

DeviceAssistant.swift (의사코드, 미검증)
import FoundationModels

// 1) 어떤 모델이든 같은 세션 API — 온디바이스, PCC, Claude를 상황에 따라 교체
let onDevice = SystemLanguageModel.default
let cloud    = PrivateCloudComputeLanguageModel()          // 인증 불필요, 32K 컨텍스트
// let claude = ClaudeLanguageModel(name: .sonnet5, auth: .appAttest(clientID: "..."))

let model: any LanguageModel = cloud.availability == .available ? cloud : onDevice

// 2) 툴 정의 — 내 앱이 PC에 연결된 상태를 모델에게 알려주는 도구
struct ConnectedDevicesTool: Tool {
    let name = "listConnectedDevices"
    let description = "현재 이 iPhone과 연결된 PC 목록과 연결 방식(WiFi/BLE)을 반환한다"
    @Generable struct Arguments { }
    func call(arguments: Arguments) async throws -> String {
        return DeviceRegistry.shared.snapshot().json   // 앱 내부 상태
    }
}

// 3) 세션 생성 + 이미지 첨부 프롬프트
let session = LanguageModelSession(
    model: model,
    tools: [ConnectedDevicesTool(), OCRTool()],
    instructions: "사용자의 PC-모바일 연동 앱 도우미다. 한국어로 짧게 답한다."
)

let screenshot: UIImage = ...   // PC에서 미러링된 화면 캡처
let response = try await session.respond {
    "이 PC 화면에서 에러 메시지를 읽고, 연결된 기기 중 어느 쪽 문제인지 판단해줘"
    Attachment(screenshot).label("pcScreen")
}
print(response.content, response.usage.output.totalTokenCount)
PCC 무료 자격의 함정 — 조건은 App Store Small Business Program 가입 + 개발자 계정 전체 앱의 누적 첫 다운로드 200만 미만이다. 과거에 인기 앱 하나만 있어도 탈락하고, 유료 티어가 없다. 커뮤니티에서 "PCC is DOA"라는 비판이 나온 이유다. 200만을 넘기면 6개월 이전 유예를 준다. 온디바이스 모델은 무제한이므로, PCC 의존도가 높은 기능은 처음부터 폴백을 설계해야 한다.

App Intents / App Schemas — 내 앱을 Siri에게 여는 방법

Siri AI가 서드파티 앱을 "이해"하고 "실행"하는 유일한 경로다. 핵심 개념은 App Schema — App Intent의 특수화된 형태로, Siri가 이미 처리 방법을 아는 모양으로 인텐트를 선언하는 계약이다. 매크로 @AppIntent(schema:), @AppEntity(schema:), @AppEnum(schema:)로 적용하고, 관련 스키마를 빠뜨리면 Xcode가 빌드 시점에 Fix-It을 띄운다.

스키마 도메인 — 어디까지 Siri가 닿는가

분류도메인Siri AI 노출
Primary (Siri AI 실행 가능)Audio, Calendar, Camera, Clock, Files, Mail, Maps, Messages, Notes, Phone, Photos, Reminders, System(searchInApp)가능
Single-purposeAssistant(일본 전용, 사이드버튼 음성앱), Visual Intelligence(semanticContentSearch)특정 진입점만
Shortcuts 전용Books, Browser, Journaling, Presentation, Reader, Spreadsheet, Whiteboard, Word processor불가 — Shortcuts에서만

주목할 점은 Settings, Bluetooth 액세서리, Continuity, HomeKit 제어용 새 도메인이 없다는 것이다. 기기 연동 앱은 "Files"(파일 전송)나 "System.searchInApp" 정도에 걸치거나, 스키마 없는 일반 App Intent로 Shortcuts·Spotlight 경로를 쓰게 된다.

SendToPCIntent.swift (의사코드, 미검증)
import AppIntents

// 화면에 보이는 파일을 엔티티로 노출 + Spotlight 시맨틱 인덱스에 등록
@AppEntity(schema: .files.file)
struct TransferFile: IndexedEntity {
    var id: String
    var name: String
    @Property(indexingKey: \.contentDescription) var summary: String
    var url: URL
}

// 30초를 넘는 전송을 Live Activity로 진행률 표시하며 실행
@AppIntent(schema: .files.shareFile)     // 실제 스키마명은 문서 확인 필요
struct SendToPCIntent: LongRunningIntent, CancellableIntent {
    @Parameter var file: TransferFile
    @Parameter var target: PCDevice          // 내 앱의 AppEntity

    func perform() async throws -> some IntentResult & ProvidesDialog {
        try await performBackgroundTask { progress in
            for await sent in Transfer.stream(file.url, to: target) {
                progress.completedUnitCount = sent
            }
        }
        return .result(dialog: "\(file.name)을(를) \(target.name)으로 보냈습니다")
    }
    func onCancel(reason: CancellationReason) { Transfer.abort() }
}

// SwiftUI 화면에서 보이는 항목을 Siri가 가리킬 수 있게 주석
List(files) { f in
    FileRow(f).appEntityIdentifier(EntityIdentifier(for: TransferFile.self, id: f.id))
}

Shortcuts 변화

Shortcuts는 iOS 27에서 "Describe a Shortcut"으로 자연어 설명만으로 단축어를 생성한다. Apple의 예시: "매일 저녁, 첫 캘린더 일정 기준으로 내일 알람을 맞추고 수면 집중모드를 켜고 침실 조명을 어둡게", "Magic Keyboard가 연결되면 창 배치 변경", "배송 알림이 오면 현관등 켜기". iOS 26의 "Use Model" 액션은 웹 지식이 추가됐고, 자동화가 단축어 편집기 안으로 통합됐다. 이 조합이 현재 Apple 플랫폼에서 사용자가 직접 만들 수 있는 유일한 멀티스텝 에이전트다.

기기 연동 관점 — Continuity, Bluetooth Channel Sounding, Wi-Fi Aware, DMA

PC↔모바일 연동 앱을 만드는 입장에서 WWDC26에서 실제로 바뀐 것을 골라냈다. Apple Intelligence와 직접 관계는 없지만 "기기 제어 에이전트"를 만들 때 쓰게 될 재료들이다.

iPhone Mirroring (macOS 27)

  • 미러링 창이 자유롭게 리사이즈된다(기존 3개 프리셋). iOS 27 SDK로 빌드하면 iOS 앱이 iPad와 iPhone Mirroring에서 자동으로 리사이즈 가능해진다. SwiftUI는 무료, UIKit 커스텀 뷰는 Auto Layout·trait collection 대응 필요.
  • Control Center 접근(Cmd+4), DRM 영상 재생 가능(기존 검은 화면).
  • 서드파티가 iPhone Mirroring 스트림에 접근하는 API는 여전히 없다.

Bluetooth Channel Sounding (iOS 27 신규, 세션 369)

  • Core Bluetooth의 CBChannelSoundingSessionConfiguration으로 실제 거리 측정, Nearby Interaction의 NINearbyAccessoryConfiguration(bluetoothChannelSoundingIdentifier:)로 거리+방향(카메라 보조).
  • 조건: iOS 27 + N1 칩 탑재 iPhone, 포그라운드 전용. 액세서리는 BT 6.3, mode-0/mode-2 필요. AccessorySetupKit으로 페어링.
  • PC가 BT 6.x Channel Sounding을 지원하면 "책상 위 어느 PC가 가장 가까운지"를 UWB 없이 판별하는 근접 자동 연결 시나리오가 열린다.

Wi-Fi Aware

  • 프레임워크 범위는 그대로 — iOS/iPadOS 26.0+만, macOS·visionOS 미지원. 백그라운드 사용은 BackgroundTasks로 허용. WWDC26에 "What's new in Wi-Fi Aware" 세션은 없었다.
  • 표준 NAN이라 Android·Wi-Fi Aware 인증 PC와 통신 가능. Windows 쪽은 Wi-Fi 드라이버 지원 여부에 달렸다.

왜 Apple은 이렇게 하는가

  • 프라이버시: PCC 데이터는 Apple도 접근 불가, 외부 전문가가 검증 가능. Federighi: "AI에서 프라이버시는 협상 대상이 아니다."
  • 결정론과 확인 UX: 세션 343에서 Apple은 "의도치 않은 부작용은 LLM의 알려진 위험"이라며 부작용 있는 인텐트에 자동 확인을 넣었다. The Information 보도에 따르면 Apple은 모든 에이전트 액션이 "사전에 열거되고 검증"되길 원한다.
  • macOS 27은 오히려 조인다: TCC 데이터베이스가 보호 컨테이너로 이동, 비샌드박스 앱의 Application Support 보호 확대, MDM이 부여한 접근성 권한도 사용자가 끌 수 있게 변경. 에이전트에 문을 열지도 닫지도 않았지만 주변 데이터 접근은 강화됐다.
