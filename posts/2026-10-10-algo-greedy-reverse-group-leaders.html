바로 앞 그룹의 실제 위치
추월이 불가능한 한 줄 달리기에서, 뒤 선수가 앞 선수를 따라잡으면 그때부터 앞 그룹의 속도로 함께 달린다. time이 지난 뒤 각 그룹의 선두 번호를 구하는 문제다. 언제 누가 누구를 따라잡는지 시간순으로 시뮬레이션할 필요가 없다. 맨 앞 선수부터 거꾸로 보면서 "막히지 않았다면 도착했을 위치"와 "바로 앞 그룹의 실제 위치"만 비교하면 된다. 학습 교재 08단원 예제 코드를 추적한 기록이며, 그룹 구성원과 위치까지 구하는 변형을 덧붙였다 (Python 3 실행 확인).

문제

초기 위치가 서로 다른 선수들이 한 방향으로 달린다. 추월은 불가능하다. 뒤 선수가 앞 선수를 따라잡으면 이후로는 앞 그룹의 속도에 맞춰 함께 달린다. time 후 각 그룹의 선두 선수 번호를 가장 앞선 그룹부터 구한다.

  • 입력: positions — 서로 다른 초기 위치의 오름차순 리스트. speeds — 같은 길이의 양의 속도 리스트. time — 음이 아닌 시간.
  • 번호는 입력 순서대로 1부터 시작한다.
  • 도착 위치가 같은 선수들은 한 그룹이다.
  • 출력: 선두 번호 리스트. 가장 앞선 그룹이 먼저 온다.
positionsspeedstime출력
[0, 2, 6, 9, 12][2, 2, 1, 3, 2]6[5, 3]
[0, 2, 6, 9, 12][2, 2, 1, 3, 2]1[5, 4, 3, 2, 1]
[0, 2][3, 1]1[2]
[0][5]10[1]

전체 코드

group_leaders.py
def group_leaders(positions, speeds, time):
    leaders = []
    front_position = None
    for i in range(len(positions) - 1, -1, -1):
        free_position = positions[i] + speeds[i] * time
        if front_position is None or free_position < front_position:
            leaders.append(i + 1)
            front_position = free_position
        # 합류할 때는 앞 그룹의 위치를 변경하지 않는다.
    return leaders


def run_checks():
    assert group_leaders([0, 2, 6, 9, 12], [2, 2, 1, 3, 2], 6) == [5, 3]
    assert group_leaders([0, 2, 6, 9, 12], [2, 2, 1, 3, 2], 1) == [5, 4, 3, 2, 1]
    assert group_leaders([0, 2], [3, 1], 1) == [2]
    assert group_leaders([0], [5], 10) == [1]
    print("08단원: 확인용 테스트 4개 통과")


if __name__ == "__main__":
    run_checks()

핵심 아이디어

왜 뒤에서부터 보는가

한 선수의 최종 위치는 자기보다 앞에 있는 선수들에게만 영향을 받는다. 뒤에서 누가 쫓아오든 내 위치는 바뀌지 않는다. 맨 앞 선수는 아무에게도 막히지 않으므로 최종 위치가 바로 정해진다. 그다음 선수는 맨 앞 선수의 결과만 알면 정해지고, 그다음도 마찬가지다. 즉 "답이 확정되는 순서"가 앞에서 뒤 방향이고, 리스트 인덱스로는 끝에서 처음 방향이다.

두 위치만 비교한다

이름의미
free_position아무에게도 막히지 않았다면 time 후에 있을 위치. 위치 + 속도 × 시간
front_position바로 앞 그룹이 time 후 실제로 있는 위치
비교 결과뜻처리
free_position < front_position앞 그룹에 닿지 못했다새 그룹의 선두. 실제 위치는 free_position
free_position >= front_position도중에 따라잡았다앞 그룹에 합류. 실제 위치는 front_position

한 줄로 줄이면 실제 위치 = min(자유 위치, 앞 그룹의 실제 위치)다. 따라잡은 시점이 언제인지는 계산하지 않는다. 처음에는 뒤에 있었는데 자유 위치가 앞 그룹의 위치 이상이라면, 그 사이 어딘가에서 반드시 만났다는 사실만으로 충분하다.

판별 기준 — 각 원소의 결과가 한쪽 방향의 원소들에만 의존하면, 의존 대상이 먼저 확정되는 방향으로 순회한다. 그러면 "지금까지의 요약값 하나"만 들고 가면서 매 원소를 즉시 결정할 수 있다. 여기서 요약값은 앞 그룹의 실제 위치다.

코드 한 줄씩 보기

끝에서 처음으로

for i in range(len(positions) - 1, -1, -1):

위치가 오름차순으로 주어지므로 마지막 인덱스가 가장 앞선 선수다. range(시작, 끝, -1)에서 끝 값 -1은 포함되지 않으므로 인덱스 0까지 돈다.

맨 앞 선수는 무조건 선두

if front_position is None or free_position < front_position:
    leaders.append(i + 1)
    front_position = free_position

front_position is None은 아직 앞 그룹이 없다는 뜻으로, 첫 반복에서만 참이다. 번호는 1부터라서 i + 1을 넣는다. 가장 앞선 선수부터 처리하므로 leaders는 자동으로 "앞선 그룹부터" 순서가 된다. 뒤집을 필요가 없다.

합류할 때는 아무것도 하지 않는다

else 절이 없다는 점이 이 코드에서 가장 중요하다. 합류한 선수는 앞 그룹과 같은 위치에 있으므로 그 뒤 선수가 비교해야 할 기준은 여전히 같은 front_position이다. 여기서 값을 free_position으로 바꾸면 "실제로는 도달하지 못한 위치"가 기준이 되어 뒤쪽 판정이 틀어진다.

예제 추적

positions = [0, 2, 6, 9, 12], speeds = [2, 2, 1, 3, 2], time = 6.

i번호자유 위치front_position판정실제 위치
4512 + 2 × 6 = 24없음선두24
349 + 3 × 6 = 272427 ≥ 24, 합류24
236 + 1 × 6 = 122412 < 24, 선두12

결과는 [5, 3]이다. 그룹은 {4, 5}와 {1, 2, 3} 두 개다.

같은 입력에서 시간만 바꿔 보면 그룹이 합쳐지는 과정이 보인다.

time출력일어난 일
0[5, 4, 3, 2, 1]출발 전. 모두 따로
2[5, 4, 3, 2, 1]아직 아무도 따라잡지 못함
3[5, 3, 2, 1]4번이 5번을 위치 18에서 따라잡음
4[5, 3, 1]2번이 3번을 위치 10에서 따라잡음
6[5, 3]1번이 3번 그룹을 위치 12에서 따라잡음
100[5, 3]더 합쳐지지 않음. 3번 그룹(속도 1)은 5번 그룹(속도 2)보다 느리다

1번은 정확히 time = 6인 순간에 3번 그룹에 닿는다. 자유 위치 12와 앞 그룹 위치 12가 같은 경우이고, 문제 정의상 도착 위치가 같으면 한 그룹이다. 비교가 <=가 아니라 <인 이유가 이 줄에 있다.

놓치기 쉬운 함정

실수입력잘못된 결과기대값
합류할 때도 front_position 갱신[0, 1, 2], [15, 19, 8], 1[3, 1][3]
같은 실수첫 번째 예제 (time = 6)[5, 3, 1][5, 3]
비교를 <=로 작성[0, 2], [3, 1], 1[2, 1][2]

세 줄 모두 잘못 짠 코드를 실행해 얻은 값이다.

1. 바로 앞 "선수"가 아니라 앞 "그룹"과 비교한다

[0, 1, 2], 속도 [15, 19, 8], 시간 1에서 자유 위치는 15, 20, 10이다. 3번은 10에 있고, 2번은 20까지 갈 수 있었지만 3번에 막혀 10에 있다. 1번의 자유 위치 15는 10 이상이므로 합류가 맞다. 합류한 2번의 자유 위치 20을 기준으로 삼으면 15 < 20이라 1번을 새 선두로 잘못 판정한다. 기준은 항상 그룹의 실제 위치다.

2. 같은 위치는 합류다

[0, 2], 속도 [3, 1], 시간 1에서 두 선수의 자유 위치는 모두 3이다. 정확히 그 순간에 따라잡은 것이므로 한 그룹이다. <=로 쓰면 동점을 새 그룹으로 처리해 선두가 하나 더 나온다.

3. 앞에서부터 순회한다

인덱스 0부터 보면 그 선수의 운명을 정할 정보(앞 선수들의 결과)가 아직 없다. 스택을 쓰거나 되돌아가 고쳐야 해서 코드가 복잡해진다. 순회 방향만 뒤집으면 변수 하나로 끝난다.

4. 번호와 출력 순서

인덱스는 0부터, 번호는 1부터다. 그리고 출력은 "가장 앞선 그룹부터"인데, 이는 번호가 큰 쪽부터라는 뜻이다. 결과를 오름차순으로 정렬하면 순서가 뒤집힌다.

5. 시간순 시뮬레이션을 짠다

따라잡는 사건을 하나씩 찾아 시간을 진행시키는 방식도 답은 맞지만, 사건마다 전체를 훑어야 해서 느리고 나눗셈 때문에 소수 오차도 신경 써야 한다. 이 풀이는 곱셈과 덧셈만 쓰므로 입력이 정수이면 계산이 정확하다. 속도나 시간이 실수로 주어지는 변형이라면 동점 비교에 오차 허용이 필요하다.

변형: 그룹 구성원과 위치까지

교재 범위를 넘어 직접 추가한 변형이다. 원본은 합류할 때 아무것도 하지 않지만, 그 자리에서 "가장 최근에 만든 그룹"에 번호를 넣으면 그룹 전체를 얻을 수 있다.

groups_at.py
def groups_at(positions, speeds, time):
    groups = []
    front_position = None
    for i in range(len(positions) - 1, -1, -1):
        free_position = positions[i] + speeds[i] * time
        if front_position is None or free_position < front_position:
            groups.append({"leader": i + 1, "members": [i + 1], "position": free_position})
            front_position = free_position
        else:
            groups[-1]["members"].append(i + 1)
    return groups


for group in groups_at([0, 2, 6, 9, 12], [2, 2, 1, 3, 2], 6):
    print(group)
# {'leader': 5, 'members': [5, 4], 'position': 24}
# {'leader': 3, 'members': [3, 2, 1], 'position': 12}

합류하는 선수는 항상 직전에 만든 그룹에 들어간다. 추월이 없어서 한 그룹은 번호가 연속한 선수들로만 이루어지기 때문이다.

검증에는 풀이와 전혀 다른 방식의 구현을 썼다. 인접한 그룹 사이에서 가장 빨리 일어나는 따라잡기를 찾아 그 시각까지 전원을 이동시키고 합치는 시간순 시뮬레이션이며, 분수로 계산해 오차를 없앴다.
