AI가 읽기 좋은 데이터의 4단계

단계할 일이유
1. 텍스트화PDF·스캔본·웹을 md로 변환이미지·스캔 PDF는 읽기 어렵고 토큰 낭비
2. 구조화헤딩 계층, 메타데이터, 1파일 1주제문맥 파악과 필요한 조각만 잘라 쓰기
3. 정제머리글·바닥글·페이지 번호·광고·OCR 오류 제거노이즈가 많으면 답변 품질 하락
4. 검색 계층인덱스, RAG, MCP 연결자료가 컨텍스트 창을 넘을 때 필수

모든 파일의 맨 위에는 YAML frontmatter를 둔다. AI가 "2025년 이후 반도체 관련 웹 자료만" 같은 조건으로 거를 수 있게 된다.

frontmatter 예시
---
title: 반도체 슈퍼사이클
source: https://example.com/article
type: web
published: 2026-09-20
tags: [반도체, HBM]
status: inbox
---

자료 규모별 AI 연결 방법

  • 소규모 (수십 개): Claude 프로젝트나 폴더 연결로 통째로 넘긴다.
  • 중규모: md 폴더를 두고 AI가 grep·파일 탐색으로 직접 찾게 한다 (에이전트 검색). 현재 가장 실용적이다.
  • 대규모 (책 수백 권): 청크 단위 임베딩 + 벡터 DB(RAG). 키워드(BM25)와 의미 검색을 섞은 하이브리드 검색이 정확도가 높다.
  • MCP 서버: 지식 저장소를 AI가 도구로 직접 조회하게 연결한다.
변환 도구 — 문서·PDF: Docling, Marker, MarkItDown / 웹: Obsidian Web Clipper, Jina Reader

저장 위치: Google Drive + md 폴더

선택지장점단점
Google Drive + md 폴더용량 넉넉, 원본 PDF 동시 보관, PC 동기화Google Docs 형식으로 저장하면 AI가 다루기 불편
Notion구조화·DB 기능, MCP 연동대용량 원본에 약함, md 추출 시 손실, 종속성
로컬 폴더만가장 빠름백업·모바일 접근 약함
  1. Drive for Desktop으로 Knowledge/ 폴더를 로컬에 동기화한다.
  2. 이 폴더를 Obsidian 보관함(vault)으로 열어 편집한다. 위키링크·태그·그래프를 쓸 수 있다.
  3. Claude(Cowork·Claude Code)나 로컬 LLM에 같은 폴더를 연결한다.
folder structure
Knowledge/
├─ AI_GUIDE.md        AI 작업 규칙 (CLAUDE.md로 복사 가능)
├─ _templates/        템플릿
├─ 00_inbox/          새로 수집, 미정리
├─ 10_sources/
│  ├─ books/          책 노트
│  ├─ web/            웹 스크랩
│  └─ notes/          개인 메모
├─ 30_insights/       재가공 결과 (핵심 자산)
└─ 90_raw/            원본 PDF·이미지

재가공이 목적이라면 30_insights가 핵심 자산이다. AI가 만든 인사이트를 다시 자료로 쌓아야 다음 재가공 품질이 올라간다. 요약은 별도 폴더 대신 각 소스 파일 안에 둔다. 원문과 요약이 한 파일에 있어야 AI가 맥락을 잃지 않는다.

클라우드 AI vs 로컬 LLM

로컬 기준은 64GB 통합 메모리 Mac (30B급 중형 모델 실사용 수준)이다.

항목클라우드 (Claude 등)로컬 (64GB Mac)
추론·통찰 품질최상위중형 모델 수준, 확실히 낮음
한 번에 읽는 양수십만~100만 토큰실사용 32K~128K, 길어지면 느려짐
여러 문서 종합강함피상적으로 흐르기 쉬움
한국어 글쓰기자연스러움모델별 편차 큼
비용구독·API사실상 무료
프라이버시외부 전송완전 로컬
대량 반복 작업비용·호출 제한 부담밤새 돌려도 부담 없음

로컬로 충분한 작업은 요약, 태그·분류, 메타데이터 추출, OCR 텍스트 정제, 임베딩, 단일 문서 질의응답이다. 반면 여러 책과 메모를 엮어 새로운 관점을 도출하거나 모순을 찾는 "인사이트" 작업은 클라우드가 확연히 낫다. 그래서 두 가지를 섞는다.

hybrid pipeline
[로컬 LLM]   대량 1차 가공: 요약 · 태깅 · 정제 · 임베딩 (무료, 반복)
     ↓
[md 저장소]  정제된 원문 + 요약 + 메타데이터
     ↓
[클라우드 AI] 인사이트 도출 · 재가공 → 30_insights 에 다시 저장

md 템플릿 5종

Obsidian 코어 플러그인 "템플릿"에서 _templates 폴더를 지정하면 {{title}}, {{date}}가 자동 치환된다.

AI 작업 가이드 파일

저장소 루트에 AI가 가장 먼저 읽는 규칙 파일을 둔다. Claude Code·Cowork라면 CLAUDE.md로 복사하면 자동으로 로드된다. 핵심 규칙은 다음과 같다.

  • 팩트와 의견을 분리하고, 원문에 없는 내용은 "추정"으로 표시한다.
  • 인사이트에는 반드시 sources에 근거 파일을 링크한다.
  • 반론·리스크 섹션을 비우지 않는다.
  • 파일을 수정하면 updated를 갱신하고 폴더 index.md에 한 줄 추가한다.
  • 원문과 90_raw/는 수정하지 않는다.

# AI 작업 가이드 (Knowledge Vault)

> 이 파일은 AI(Claude, 로컬 LLM)가 이 저장소에서 작업할 때 **가장 먼저 읽는 규칙**이다.
> Claude Code/Cowork라면 `CLAUDE.md`로 복사해도 된다.

## 1. 저장소 목적
책·웹 자료·메모를 모아 **재가공해 인사이트를 얻는 것**이 목적이다.
단순 요약보다 **여러 자료를 엮은 비교·종합·반론**을 우선한다.

## 2. 폴더 구조
| 폴더 | 내용 | AI 권한 |
|---|---|---|
| `00_inbox/` | 새로 수집, 미정리 | 읽기·정리 후 이동 |
| `10_sources/books/` | 책 노트 (tpl-book) | 읽기, 요약 섹션 채우기 |
| `10_sources/web/` | 웹 스크랩 (tpl-web) | 읽기, 요약 섹션 채우기 |
| `10_sources/notes/` | 개인 메모 (tpl-note) | 읽기 전용 |
| `30_insights/` | 재가공 결과 (tpl-insight) | 생성·수정 |
| `90_raw/` | 원본 PDF·이미지 | 읽기 전용 |
| `_templates/` | 템플릿 | 수정 금지 |

각 폴더의 `index.md`를 먼저 읽고 필요한 파일만 연다.

## 3. 메타데이터 규칙
- 모든 파일은 YAML frontmatter로 시작한다.
- `type`: `book | web | note | insight | index | guide`
- `status` 흐름: `inbox → processed → summarized → linked` (insight: `draft → reviewed → applied → revisited`)
- `tags`: 한글 명사, `#` 없이, 소문자 영문 혼용 가능. 기존 태그를 우선 재사용한다.
- 날짜: `YYYY-MM-DD`
- 링크: Obsidian 위키링크 `[[파일명]]`
- 파일명: `YYYY-MM-DD-제목.md` (web·note·insight), `저자-제목.md` (book)

## 4. 작업 규칙
1. **팩트와 의견을 분리**한다. 원문에 없는 내용은 "추정"이라고 표시한다.
2. 인사이트를 쓸 때는 반드시 `sources`에 근거 파일을 링크하고, 본문에 `[[출처]]`를 단다.
3. **반론·리스크 섹션을 비우지 않는다.**
4. `## 내 생각` 섹션은 사용자 전용이다. AI는 쓰지 않는다.
5. 파일을 수정하면 `updated` 날짜를 갱신하고, 해당 폴더 `index.md`에 한 줄 추가한다.
6. 원문(`## 원문`, `90_raw/`)은 수정하지 않는다.
7. 투자 관련 인사이트는 `review_date`를 설정한다 (기본 3개월 후).
