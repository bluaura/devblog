애플의 온디바이스 AI 개발 스택은 "누가 모델을 가져오느냐"로 네 층으로 나뉜다. Foundation Models 프레임워크는 애플 모델(온디바이스 3B / PCC)을 무료로 쓰는 세션 API이고, Core AI는 개발자가 PyTorch에서 변환한 자체 모델을 CPU·GPU·Neural Engine에서 돌리는 Core ML 후속 런타임이다. App Intents / App Schemas는 앱의 액션·콘텐츠를 Siri AI에 노출해 "인텔리전트 허브"에 참여하는 유일한 통로이며, MLX는 Mac 중심의 연구·실험용이다. 애플의 역할은 오케스트레이터·프라이버시 관리자·모델 공급자 겸 애그리게이터이고, 서드파티 앱은 툴과 콘텐츠를 제공하는 공급자가 된다. WWDC26 세션·개발자 문서·9월 9일 키노트 기준(2026-09-12)이며, 검증하지 못한 항목은 미확인으로 표기했다.

2. Core AI — Core ML의 후속 런타임

무엇이고, Core ML과는 어떤 관계인가

애플 공식 정의는 "Run AI models in your app on Apple silicon"이다. 최신 모델 아키텍처와 추론 기법을 CPU·GPU·Neural Engine에서 실행하는 프레임워크이며, 시스템의 Siri와 Apple Intelligence 자체가 이 위에서 돈다(Platforms State of the Union).

  • Core ML은 폐기되지 않았다. 문서가 서로를 교차 참조한다 — 결정 트리·테이블 피처 등 신경망 외 모델은 Core ML, 최신 아키텍처의 AI 모델은 Core AI. WWDC26에 "What's new in Core ML" 세션은 없었다. WWDC 랩에서 애플 엔지니어가 "신경망은 앞으로 Core AI로"라고 안내했다는 보고가 있다(Blake Crosley). "후속(successor)"이라는 표현은 Bloomberg·InfoQ 등 언론의 것이다.
  • 마이그레이션 변환기는 없다. .mlpackage에서 .aimodel로의 자동 변환은 없고 PyTorch에서 coreai-torch로 다시 export해야 한다. 새 파일 포맷·새 Swift 타입·새 Python 패키지로 완전히 새로운 스택이다.
  • 지원 OS: iOS·iPadOS·macOS·tvOS·visionOS·watchOS 27.0+, Apple silicon 전용. AOT 컴파일은 Apple Intelligence 지원 기기(A17 Pro+, M1+)만, tvOS·watchOS 미지원.
  • 연산 유닛: ComputeUnitKind는 .cpu / .gpu / .neuralEngine. A19·M5의 GPU Neural Accelerator는 별도 열거값 없이 GPU 경로에서 투명하게 사용된다. 백그라운드에서 Neural Engine을 쓰려면 새 entitlement com.apple.developer.background-tasks.continued-processing.inference가 필요하다.

Python 변환 파이프라인

export_qwen3.py (WWDC26-324/325 흐름 재구성, 미검증)
import torch, coreai_torch

# 1. torch.export 로 그래프 추출 (KV 캐시는 state 로 분리)
exported = torch.export.export(model, example_inputs)
exported = exported.run_decompositions(coreai_torch.get_decomp_table())

# 2. Core AI 프로그램으로 변환
conv = coreai_torch.TorchConverter()
conv.add_exported_program(
    exported,
    input_names=["tokens", "position"],
    state_names=["keyCache", "valueCache"],
    output_names=["logits"],
)
ai_program = conv.to_coreai()
ai_program.optimize()

# 3. 압축 (coreai-opt) 후 저장
from coreai_opt import Quantizer, presets
ai_program = Quantizer(presets.w4).apply(ai_program)
ai_program.save_asset("Qwen3.aimodel")
terminal
# 공식 레시피 원클릭 export (apple/coreai-models)
uv run coreai.llm.export Qwen/Qwen3-0.6B --platform iOS --compression 4bit_weights_8bit_kv_cache

# AOT 컴파일 → 아키텍처별 .aimodelc (서버에 호스팅, 기기에서 deviceArchitectureName 으로 선택)
xcrun coreai-build compile Qwen3.aimodel --platform iOS --min-deployment-version 27.0 --output compiled/

퓨즈드 연산(SDPA 어텐션, RoPE, RMSNorm, gather-matmul)이 기본 제공되고 커스텀 Metal 4 커널(TorchMetalKernel)을 .aimodel에 내장할 수 있다. 압축은 int4/int8/FP4/FP8 가중치와 팔레타이제이션(LUT)을 지원하며, SAM3 850M이 3GB에서 430MB(int4)로 줄어든 예가 세션 325에 나온다. Xcode 27 모델 뷰어, Core AI 게이지, Instruments 템플릿, 독립형 Core AI Debugger 앱이 디버그·프로파일 도구다. 특이하게 coreai-models 저장소에 Claude Code·Codex·Gemini CLI용 에이전트 스킬(working-with-coreai, model-authoring)도 들어 있다.

공식 카탈로그(apple/coreai-models): LLM — Gemma 3, GPT-OSS, Mistral, Mixtral, Phi, Qwen2.5, Qwen3(0.6B/1.7B/4B/8B), Qwen3 MoE. 확산 — Stable Diffusion 1.5/2.1/3.5 Medium, FLUX.2. VLM — Qwen3-VL. 비전 — CLIP, Depth Anything v3, EfficientSAM, SAM 3, YOLOS. 오디오 — Whisper, Parakeet TDT, Wav2Vec 2.0, CLAP. Llama는 없다(라이선스가 App Store 재배포를 막는다는 커뮤니티 해석). 세션 324의 "70B LLM 에이전틱 어시스턴트"(Mac) 시연은 모델명·양자화·tok/s가 미공개다. 미확인

출처는 john-rocky/apple-silicon-llm-bench. 저자 결론은 "소형 모델에서 Core AI GPU 우위가 크지만 8B급에서는 둘 다 메모리 대역폭에 묶여 사실상 동률"이며, iPhone 지속 부하 시 GPU 런타임 처리량이 50~60% 떨어진다. A20 Pro·M5 수치는 아직 없다.

긍정: "시스템 전역 온디바이스 모델이 OS API의 핵심이 된다는 아이디어는 매우 매력적"(HN), Foundation Models와의 합성성은 "big deal"(The Swift Dev), Gemma 4 E2B를 755MB로 실행하는 메모리 효율. 불만: MLX·coremltools와의 관계 혼란(HN), OS 27 전용이라 하위 호환 없음, 첫 실행 specialization 지연, 변환 비결정성, 베타 KV 캐시 크래시(FB23024751), iPhone 메모리 상한 약 6.4GB로 8B 디코더는 Mac 전용, Python 전용 저작, Linux 런타임 없음. HN 스레드는 367pt / 108댓글이었다.

배포 실무 — 모델을 앱 번들에 넣지 말고 Background Assets(Apple-Hosted, 앱당 200GB 무료)로 아키텍처별 .aimodelc를 내려받는 것이 애플의 명시적 권고다. On-Demand Resources는 OS 27에서 폐기됐다. iOS의 Qwen3 export는 increased-memory-limit entitlement가 필요할 수 있다. 변환 모델은 업스트림 라이선스를 상속한다(Qwen Apache-2.0, Gemma·Llama 자체 약관).

"좋지 않다"는 평가는 절반만 맞다. 동급(3~4B) 오픈 모델과는 대등하지만 프론티어와 비교하면 지식·추론·긴 컨텍스트에서 확실히 부족하다. 애플 자신도 이 모델을 "앱 안의 작은 작업" 용도로 규정하고, 큰 작업은 iOS 27부터 같은 API로 PCC·Claude·Gemini에 넘기는 하이브리드 구조를 공식화했다.

HybridSession.swift (WWDC26-241/339 패턴 재구성, 미검증)
import FoundationModels

@Generable
struct TaskItem {
    @Guide(description: "할 일 제목, 20자 이내") var title: String
    @Guide(description: "ISO 8601 날짜, 없으면 nil") var due: String?
    @Guide(.anyOf(["work", "home", "errand"])) var tag: String
}

func parseTasks(_ text: String) async throws -> [TaskItem] {
    let onDevice = SystemLanguageModel.default
    // 컨텍스트가 부족하면 같은 API 로 PCC 모델에 승격
    let needsCloud = try onDevice.tokenCount(for: Prompt(text)) > onDevice.contextSize / 2
    let model: any LanguageModel = needsCloud
        ? PrivateCloudComputeLanguageModel()
        : onDevice

    let session = LanguageModelSession(
        model: model,
        instructions: Instructions("문장에서 할 일 항목을 추출한다. 새 정보를 지어내지 않는다.")
    )
    return try await session.respond(to: text, generating: [TaskItem].self).content
}

import AppIntents
import CoreSpotlight

@AppEntity(schema: .notes.note)
struct NoteEntity: IndexedEntity {
    let id: UUID
    var title: String
    var content: String?
    var creationDate: Date?
    var defaultQuery = NoteQuery()
}

@AppIntent(schema: .notes.createNote)
struct CreateNoteIntent {
    var title: String
    var content: String?
    func perform() async throws -> some ReturnsValue<NoteEntity> {
        let note = try await NoteStore.shared.create(title: title, content: content)
        // "donation amnesia" 방지: 선언만 하지 말고 실제로 인덱싱한다
        try await CSSearchableIndex.default().indexAppEntities([note])
        return .result(value: note)
    }
}

Crosley — 스키마 채택은 "struct 세 개와 코드 스니펫 몇 개", 함정은 IndexedEntity 선언만 하고 indexAppEntities를 안 부르는 "donation amnesia". Dracode — App Intents 없는 앱은 "Siri의 가장 강력한 표면에서 보이지 않는다".

비판·우려: Viticci — 서드파티 지원 "일관성 없음", 애플 자체 앱도 없는 기능을 환각. Engadget — Crunchyroll은 되고 Gmail은 안 됨. Manton Reece — 애플의 "거의 광신적인 프라이버시 집착"이 데이터 사일로를 만든다. EU/DMA — 애플은 "다른 가상 비서에게 사용자 개인 데이터와 다른 앱 제어 권한을 줘야 한다"는 해석 때문에 iOS 27 Siri AI를 EU에서 보류했고, EU 개발자는 iOS에서 Siri AI를 테스트할 수 없다. 이 싸움의 본질은 "애플 외 에이전트가 App Intents·개인 컨텍스트에 접근할 수 있는가"다.

7. 기기 연동 앱 관점의 시사점

파일 전송·미러링·화면 확장처럼 PC와 모바일을 잇는 앱이라면 이 스택에서 열리는 지점은 세 곳이다.

  1. 액션·엔티티 노출로 허브의 손발이 되기. "이 파일을 내 PC로 보내" 같은 요청이 Siri AI에서 동작하려면 앱이 @AppEntity(기기, 세션, 전송 항목)와 @AppIntent를 노출해야 한다. 다만 공식 Siri 도메인 12개에 "기기 연결/전송" 도메인은 없다 — 현재는 .system.searchInApp과 비스키마 App Intents(Shortcuts·Spotlight 경로), Transferable + IntentValueRepresentation으로 다른 앱의 콘텐츠를 받아 전송하는 형태가 현실적 경로다. LongRunningIntent로 30초 이상 걸리는 전송을 Live Activity로 표시할 수 있다.
  2. Mac 쪽 대형 모델 + iPhone 쪽 소형 모델의 분업. Core AI는 같은 .aimodel을 iOS(0.6B~4B)와 macOS(8B~70B)에 배포할 수 있고, LanguageModel 프로토콜 덕에 iPhone 앱이 Mac 앱의 fm serve(OpenAI 호환 엔드포인트)나 자체 gRPC 서버 위의 모델을 또 하나의 프로바이더로 세션 뒤에 꽂을 수 있다. LM Studio가 WWDC26에서 시연한 "Mac Studio 클러스터 모델을 iPhone에서 LM Link로 원격 접속"이 정확히 이 패턴이다.
  3. 에이전트 툴 노출 경로는 아직 애플 폐쇄형. 외부 에이전트(OpenClaw·Claude·MCP 클라이언트)가 iOS 앱의 App Intents를 직접 호출하는 경로는 없다. Mac에서는 앱이 자체 MCP 서버를 띄우는 방식이 가능하지만 iOS에서는 Shortcuts·App Intents만이 공식 통로다. EU DMA 결과에 따라 이 경계가 바뀔 수 있다.

8. 정리

질문답
Core AI로 무엇을 만들 수 있나자체 오픈 모델(Qwen3·Gemma·Whisper·SAM3·FLUX)을 내장한 카메라 VLM, 전사, 세그멘테이션, 이미지 생성(Mac), 에이전틱 어시스턴트(Mac). iPhone은 약 6GB 메모리 한계로 4B 이하가 현실적
Foundation Models는 쓸 만한가동급 3~4B 오픈 모델과 대등, 프론티어와는 비교 불가. 무료·오프라인·@Generable이 강점, 4K 컨텍스트(한국어는 더 짧음)·환각·기기 제한이 약점. iOS 27부터 같은 API로 PCC·Claude·Gemini 승격이 가능해 하이브리드 설계가 정답
Intelligent hub에서 앱의 역할Siri라는 에이전트에게 툴(App Schemas)과 콘텐츠(IndexedEntity)를 제공하는 공급자. 대화·확인·오케스트레이션·과금은 애플이 쥠
애플의 역할프라이버시 관리자 · 오케스트레이터 · 모델 공급자 · 모델 애그리게이터 · 하드웨어. 외부 에이전트에는 아직 문을 열지 않음(MCP 없음, EU DMA 분쟁 중)
지금 해야 할 것App Schemas + IndexedEntity 채택(허브 밖에 있지 않기 위해), Foundation Models로 앱 데이터 위 소형 작업부터, 큰 모델이 필요하면 Core AI(Mac) 또는 PCC/외부 프로바이더

미확인 항목: 70B 시연 모델의 정체·tok/s, iOS 27 온디바이스 컨텍스트 기기별 정확값, AFM 3 Core Advanced의 서드파티 접근 가능 여부, PCC 200만 DL 초과 시 가격, OS 27용 어댑터 툴킷, Siri용 OS 레벨 MCP·챗봇 Extensions, 개발자 수수료 정책. 본문의 코드는 WWDC 세션 패턴을 재구성한 것으로 실기기에서 검증하지 않았으며, iOS 27 정식 출시(9월 14일) 이후 API가 바뀔 수 있다.
