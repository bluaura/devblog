한 종류를 제거해 최장 연속 구간 만들기 — 후보 열거 풀이와 O(N) 개선

예제 결과

O(N)
구간 압축 후 1회 순회
일렬로 놓인 상품에서 한 종류를 통째로 제거했을 때, 남은 것 중 같은 종류가 가장 길게 이어지는 길이를 최대로 만드는 문제다. 제거할 종류를 하나씩 전부 시도하고(후보 열거), 매번 한 번의 순회로 최장 연속 길이를 센다. 동점이면 종류 번호가 큰 쪽을 고르는데, 이 규칙은 튜플 비교 한 줄로 끝난다. 학습 교재 03단원 예제 코드를 추적한 기록이며, 마지막에 O(N) 개선 버전을 덧붙였다 (Python 3 실행 확인).

문제

상품 종류가 일렬로 놓여 있다. 한 종류의 상품을 모두 제거한 뒤, 남은 상품에서 같은 종류가 연속으로 이어지는 최장 길이를 최대화한다.

  • 입력: values — 비어 있지 않은 양의 정수 리스트. 각 값이 상품 종류다.
  • 출력: (최장 길이, 제거 종류) 튜플.
  • 동점이면 제거할 종류 번호가 큰 것을 고른다.
  • 제거 후 아무것도 남지 않으면 최장 길이는 0이다.
입력출력이유
[1, 2, 1, 1](3, 2)2를 빼면 1이 세 개 이어진다
[1, 2](1, 2)어느 쪽을 빼도 길이 1, 동점이라 큰 번호 2
[5, 5, 5](0, 5)후보가 5뿐이고 빼면 비어 버린다
[1, 2, 1, 2, 1](3, 2)2를 빼면 떨어져 있던 1 세 개가 붙는다

전체 코드

best_removal.py
def best_removal(values):
    best_length = -1
    best_kind = -1
    for removed in set(values):
        previous = None
        run = 0
        longest = 0
        for value in values:
            if value == removed:
                continue
            if value == previous:
                run += 1
            else:
                run = 1
            previous = value
            longest = max(longest, run)
        if (longest, removed) > (best_length, best_kind):
            best_length, best_kind = longest, removed
    return best_length, best_kind


def run_checks():
    assert best_removal([1, 2, 1, 1]) == (3, 2)
    assert best_removal([1, 2]) == (1, 2)
    assert best_removal([5, 5, 5]) == (0, 5)
    assert best_removal([1, 2, 1, 2, 1]) == (3, 2)
    print("03단원: 확인용 테스트 4개 통과")


if __name__ == "__main__":
    run_checks()

핵심 아이디어

이 문제는 두 개의 작은 문제를 겹쳐 놓은 구조다.

  1. 후보 열거 — 제거할 수 있는 종류는 리스트에 실제로 등장한 값뿐이다. set(values)로 후보를 뽑아 하나씩 전부 시도한다.
  2. 연속 구간 세기 — 후보 하나를 정했으면, 그 종류를 건너뛰면서 "직전 값과 같으면 +1, 다르면 1로 리셋"하는 순회 한 번으로 최장 길이를 구한다.
  3. 최적 후보 갱신 — (길이, 종류) 튜플을 비교해 더 큰 쪽을 남긴다. 길이가 우선이고, 같으면 종류 번호가 큰 쪽이 이긴다.
판별 기준 — "하나를 골라 없애고(바꾸고) 결과를 최대화"하는 문제에서 고를 수 있는 후보 수가 작으면, 먼저 전부 시도하는 풀이를 세운다. 정답이 확실한 풀이가 있어야 이후 최적화 버전을 대조 검증할 수 있다.

코드 한 줄씩 보기

후보는 set으로 뽑는다

for removed in set(values):

등장하지 않은 종류를 제거하는 것은 의미가 없으므로 후보는 등장한 값의 집합이면 충분하다. set의 순회 순서는 보장되지 않지만, 아래에서 튜플로 비교하기 때문에 어떤 순서로 돌아도 결과가 같다.

제거된 값은 없는 것처럼 건너뛴다

if value == removed:
    continue

이 풀이의 핵심 줄이다. 실제로 리스트에서 원소를 지우지 않고 continue로 넘어간다. 중요한 점은 이때 previous와 run을 건드리지 않는다는 것이다. 그래서 [1, 2, 1]에서 2를 제거하면, 2를 지나친 뒤에도 previous가 1로 남아 있어 양옆의 1이 한 구간으로 이어진다.

연속 길이 세기

if value == previous:
    run += 1
else:
    run = 1
previous = value
longest = max(longest, run)

run은 현재 이어지고 있는 구간의 길이, longest는 지금까지 본 구간 중 최댓값이다. previous의 초기값이 None이라 첫 원소는 항상 else로 들어가 run = 1이 된다. 입력이 양의 정수뿐이므로 None과 겹칠 일이 없다.

튜플 비교로 동점 처리

if (longest, removed) > (best_length, best_kind):
    best_length, best_kind = longest, removed

파이썬 튜플은 앞 원소부터 사전식으로 비교한다. 길이가 더 길면 무조건 이기고, 길이가 같을 때만 종류 번호를 본다. "동점이면 번호가 큰 것"이라는 조건을 별도 if 없이 한 줄로 표현한 것이다. 초기값이 (-1, -1)이라 첫 후보는 길이가 0이어도 반드시 채택된다.

예제 추적

[1, 2, 1, 2, 1]을 후보별로 따라가 본다.

제거 종류남는 값최장 길이비교 튜플
1[2, 2]2(2, 1)
2[1, 1, 1]3(3, 2)

(3, 2) > (2, 1)이므로 답은 (3, 2)다.

동점이 나는 [1, 1, 2, 2]도 확인한다.

제거 종류남는 값최장 길이비교 튜플
1[2, 2]2(2, 1)
2[1, 1]2(2, 2)

길이는 둘 다 2지만 (2, 2) > (2, 1)이라 종류 2가 선택된다. 답은 (2, 2).

놓치기 쉬운 함정

1. 제거 지점에서 구간을 끊어 버린다

제거된 값을 만났을 때 run = 0이나 previous = None으로 리셋하면 [1, 2, 1, 2, 1]의 답이 3이 아니라 1이 된다. 제거는 "빈칸을 남기는 것"이 아니라 "당겨 붙이는 것"이다. 건너뛸 때는 상태를 그대로 둔다.

2. 동점 규칙을 순회 순서에 맡긴다

if longest >= best_length처럼 쓰고 "나중에 나온 후보가 이긴다"에 기대면, set 순회 순서가 오름차순이라는 보장이 없어서 틀릴 수 있다. sorted(set(values))로 순서를 고정하거나, 이 코드처럼 종류 번호를 비교 대상에 직접 넣는다.

3. 전부 사라지는 경우

[5, 5, 5]는 후보가 5 하나뿐이고 제거하면 리스트가 빈다. 안쪽 순회가 전부 continue로 끝나 longest는 0으로 남고, 답은 (0, 5)다. longest를 0으로 초기화해 둔 덕에 별도 분기가 필요 없다.

4. 종류 수가 많으면 느려진다

후보마다 리스트 전체를 순회하므로 시간 복잡도는 O(K·N)이다 (K는 종류 수, N은 리스트 길이). 모든 값이 서로 다르면 K = N이 되어 O(N²)까지 간다. 입력 제한이 작다면 이 풀이로 충분하고, 크다면 다음 절의 방법이 필요하다.

O(N)으로 줄이기

교재 범위를 넘어선 변형으로, 직접 추가한 버전이다. 관찰은 두 가지다.

  • 종류 x를 제거했을 때 결과에 영향을 주는 것은 x 구간 양옆이 같은 종류일 때 생기는 병합뿐이다. 나머지 구간은 그대로다.
  • 병합은 a x a x a처럼 같은 종류 a가 x를 사이에 두고 반복되는 "사슬" 단위로 일어난다.

그래서 먼저 리스트를 (종류, 길이) 구간으로 압축하고, 사슬마다 합을 구해 "x를 제거하면 얻는 병합 길이"를 기록한다. 병합이 없더라도 x가 아닌 종류의 기존 최장 구간은 남으므로, 종류별 최장 길이 상위 2개를 따로 들고 있으면 된다.

best_removal_fast.py
from itertools import groupby

def best_removal_fast(values):
    runs = [(kind, len(list(group))) for kind, group in groupby(values)]
    n = len(runs)

    # 1) 제거와 무관하게 이미 존재하는 구간: 종류별 최장 길이
    own = {}
    for kind, length in runs:
        own[kind] = max(own.get(kind, 0), length)
    top = sorted(((length, kind) for kind, length in own.items()), reverse=True)[:2]

    # 2) 제거로 이어 붙는 구간: a x a x a 형태의 사슬
    merged = {}
    for i in range(n - 2):
        kind = runs[i][0]
        sep = runs[i + 1][0]
        if runs[i + 2][0] != kind:
            continue
        if i >= 2 and runs[i - 2][0] == kind and runs[i - 1][0] == sep:
            continue  # 사슬의 시작점이 아님
        total = runs[i][1]
        j = i
        while j + 2 < n and runs[j + 1][0] == sep and runs[j + 2][0] == kind:
            j += 2
            total += runs[j][1]
        merged[sep] = max(merged.get(sep, 0), total)

    best = (-1, -1)
    for removed in own:
        untouched = next((length for length, kind in top if kind != removed), 0)
        best = max(best, (max(untouched, merged.get(removed, 0)), removed))
    return best

각 구간은 사슬 확장 과정에서 상수 번만 방문되므로 압축 이후 처리는 구간 수에 비례한다. top을 구할 때 전체 정렬을 썼기 때문에 엄밀히는 O(N + K log K)이고, 상위 2개만 순회로 고르면 O(N)이 된다.

무작위 대조길이 1~12, 종류 1~4, 20만 건전부 일치

실행 시간은 클라우드 컨테이너에서 한 번 측정한 값이라 환경에 따라 달라진다. 비율(약 400배)만 참고한다. 개선 버전은 원본과 무작위 대조로만 검증했고, 별도의 채점 서버에 제출한 코드는 아니다.

정리

항목후보 열거구간 압축
시간 복잡도O(K·N), 최악 O(N²)O(N + K log K)
추가 공간O(K) — 후보 집합O(N) — 구간 목록
구현 난이도낮음, 실수 여지 적음사슬 시작점 판정이 까다로움
쓰는 시점입력이 작거나 정답 기준이 필요할 때종류 수가 많고 N이 클 때
  • 제거할 후보는 set(values), 제거는 continue로 표현한다. 건너뛸 때 previous와 run을 유지해야 양옆이 이어진다.
  • 우선순위가 여러 개인 최댓값 선택은 (1순위, 2순위) 튜플 비교로 쓴다. 순회 순서에 의존하지 않는다.
  • 느리지만 확실한 풀이를 먼저 만들고, 빠른 풀이는 그것과 무작위 대조해 검증한다.
