지금 일어나는 일

개발 방식: 프롬프트에서 시스템 설계로

에이전트 개발에서 다루는 층위가 네 단계로 정리됐다. 프롬프트는 이 중 개선 여지가 가장 작은 층으로 평가된다.

층위다루는 대상비고
프롬프트 엔지니어링한 번의 메시지개선 여지가 가장 작음
컨텍스트 엔지니어링모델이 보는 정보 전체무엇을 넣고 뺄지 결정
루프 엔지니어링반복 주기, 종료 조건, 실패 처리2026년 6월 Google의 Addy Osmani가 명명
하네스 엔지니어링도구, 샌드박스, 권한, 상태, 관측2026년 2~3월 확산. "Agent = Model + Harness"
  • 스펙 주도 개발이 퍼지고 있다. 명세 → 계획 → 작업 분해 → 구현 순서이고, 프로젝트 규칙은 AGENTS.md, CLAUDE.md 같은 파일에 둔다. 작은 수정에는 과하고, 스펙과 코드가 어긋나는 문제는 남아 있다.
  • Stripe는 사내 에이전트가 주당 약 1,300개 PR을 만들지만, 사람의 코드 리뷰를 필수 관문으로 유지한다. 사내 도구는 MCP 서버로 에이전트에 연결했다.
  • 모바일 툴체인도 에이전트용으로 열렸다. Xcode 26.3(2026년 2월)은 에이전트가 빌드, 프리뷰 확인, 수정을 반복하게 하고 MCP를 지원한다. Android CLI 1.0(2026년 5월)은 IDE 없이 린트, Compose 프리뷰, UI 테스트, 가상 기기 배포를 에이전트에 제공한다.

도메인 지식의 구조화

  • 기업의 업무 객체, 관계, 허용 행동을 타입으로 정의한 온톨로지가 에이전트의 제어 계층으로 다뤄진다. 예: "금액이 기준을 넘으면 특정 역할의 승인이 있어야 지급 실행".
  • 목적은 감사 가능성이다. "에이전트가 어떤 승인 후 어떤 객체에 무엇을 했는가"를 기록으로 남긴다.

토큰 비용

  • 에이전트 배포는 챗봇 대비 10~100배 비싸다. Uber는 2026년 AI 예산을 4개월 만에 소진했다.
  • 토큰 사용량으로 직원을 줄 세우던 방식은 역풍을 맞았다. Meta는 토큰 사용 상위 250명 리더보드를 만들었다가 삭제했고, Amazon에서는 직원들이 리더보드를 조작했다. 평가 기준이 완료한 작업, 절감한 시간 같은 결과 지표로 옮겨 가고 있다.
  • GitHub Copilot은 2026년 6월 1일 사용량 과금으로 전환했다.
  • 1만 명 규모 기업을 가정한 연구에서 작업 난이도별 모델 라우팅으로 14~21% 절감이 나왔다. 항상 로드되는 컨텍스트가 무거운 설정은 세션당 비용이 3~4배였다.

회사는 어떻게 바뀌고 있나

인력 감축과 AI 재배치가 동시에

  • 직무가 합쳐진다. LinkedIn은 PM, 디자이너, 프론트엔드, 백엔드를 "풀스택 빌더" 하나로 통합했다.
  • FDE(Forward Deployed Engineer) 채용이 급증했다. 고객 현장에서 문제를 정의하고 구현하는 역할로, 채용 공고가 전년 대비 1,000% 이상 늘었다. 요구 역량에서 고객 발굴, 요구 분석, 문제 분해 비중이 커지고 있다.
  • 과금이 좌석제에서 사용량·성과 기반으로 이동한다. Adobe는 성과 기반 과금을 발표했고, 고객지원 에이전트는 해결 건당 0.99~2달러 수준이다.
  • 토큰이 보상과 투자 수단으로 거론된다. Nvidia의 젠슨 황은 기본급의 절반 수준 토큰 예산을 제안했고, OpenAI가 YC 스타트업에 200만 달러 상당 토큰을 지분 대가로 제안했다는 보도가 있다.
  • 고용 지표는 엇갈린다. 실리콘밸리의 2026년 상반기 해고는 7,295명으로 2025년 연간의 91%지만, 6월 실업률은 3.9%다.
  • 신입 채용이 줄었다. Stanford 분석에서 AI 노출이 큰 직군의 22~25세 고용이 덜 노출된 또래 대비 19% 낮다(1년 전 15%). 해고가 아니라 신규 채용 감소가 원인이고, 암묵지에 의존하는 경력자 고용은 늘었다.

개발자 업무는 어떻게 바뀔까

위 사실에서 가까운 미래로 추론한 내용이다.

  • 작성에서 검증으로. 코드 생성은 싸지고 리뷰가 병목이 된다. 테스트, CI, 작은 배치가 약한 팀은 속도가 오를수록 장애가 는다.
  • 한 명이 여러 에이전트를 운영한다. 작업을 쪼개 위임하고 결과를 합치는 일이 늘어난다. 긴 작업일수록 실패율이 높아 분해 능력이 성과를 가른다.
  • 명세가 핵심 산출물이 된다. 수용 기준, 인터페이스, 비목표를 명확히 쓰는 능력이 구현 속도를 좌우한다. PM과 개발자의 경계가 흐려진다.
  • 유지보수는 사람 몫이 오래 남는다. 레거시, 리팩터링, 호환성처럼 맥락 의존이 큰 일에서 에이전트 품질이 낮기 때문이다.
  • 실기기·무선 환경 검증은 자동화가 늦다. 에이전트용 도구가 가상 기기와 프리뷰 중심이라, 실제 기기 간 연결(BLE, Wi-Fi) 검증은 사람과 테스트 인프라에 의존할 가능성이 크다.
  • 비용이 개인·팀 지표가 된다. 토큰 사용량이 아니라 결과 대비 비용으로 평가받는 방향이다.
  • 주니어 육성 경로가 좁아진다. 신규 채용이 줄어, 팀 차원에서 리뷰와 설계 경험을 의도적으로 쌓게 할 필요가 생긴다.

무엇을 준비하면 좋은가

  1. 검증 인프라 먼저. 자동 테스트, CI, 작은 PR 단위가 AI 효과의 전제 조건이다.
  2. 에이전트가 읽을 수 있는 코드베이스. AGENTS.md, 빌드·테스트 명령, 아키텍처 규칙을 문서화하고, 사내 도구는 MCP로 연결한다.
  3. 명세 작성 훈련. 관찰 가능한 동작, 제외 범위, 인터페이스, 수용 기준, 제약 다섯 가지를 짧게 쓴다.
  4. 하네스·루프 이해. 도구 권한, 종료 조건, 실패 처리, 관측을 직접 설계해 본다. 에이전트를 쓰지 말아야 할 때를 아는 것도 포함된다.
  5. 평가(eval) 역량. 결과가 맞는지 판정하는 기준과 테스트 세트를 만드는 능력이 채용에서도 핵심으로 꼽힌다. Meta는 AI 사용을 허용하는 코딩 면접을 시험 중이다.
  6. 비용 감각. 작업별 모델 선택, 캐싱, 컨텍스트 다이어트를 익힌다.
  7. 도메인 지식의 명문화. 프로토콜 상태 전이, 정책, 예외 규칙처럼 팀만 아는 지식을 상태와 제약 형태로 정리해 두면 에이전트 활용의 자산이 된다.
  8. 고객·문제 정의 역량. FDE 공고에서 가장 빠르게 늘어난 요구는 고객 발굴, 요구 분석, 문제 분해다.
